# Сприяння

Внески вітаються через проблеми та запити на вилучення.

## Обсяг проекту

MeshMill робить великі, щільні або складні файли сітки керованими для подальшого редагування та
виробничі робочі процеси. Внески мають покращити перевірку геометрії, сітку та щільність точок
керування, оптимізація, вибір, кадрування, очищення, перевірка, обмін STL, продуктивність,
або координація цих операцій.

Проект не включає моделювання загального призначення, ліплення, малювання, анімацію, візуалізацію,
композиція сцени, матеріали, оснащення або інші системи створення контенту. Пропозиції, що вводять
ці функції виходять за рамки проекту.

Нові функції мають зосередити програму, зберегти прямі робочі процеси, які перетворюються на джерело
геометрію в керовані сітки та уникайте перетворення допоміжних елементів керування на загальне редагування
середовище.

## Локалізація

Вихідний текст інтерфейсу користувача англійською мовою зберігається в `locales/en-US.json`. Метадані мови зберігаються в
`locales/manifest.json`. Перекладені каталоги інтерфейсу користувача використовують однакові стабільні ключі та назву файлу
`<locale>.json`. Перекладена документація використовує відповідну кореневу назву файлу під
`docs/locales/<locale>/`.

Переклади спочатку створюються за допомогою зовнішніх служб машинного перекладу та отримуються
автоматизована структурна перевірка. Цей процес не може гарантувати природний, технічно точний або
контекстно правильна мова. Носіям мови пропонується переглянути та виправити переклад інтерфейсу користувача
текст і документація. Виправлення перекладу повинні зберігати ключі каталогу, заповнювачі,
команди, посилання, вимірювання, назви продуктів і структуру Markdown.

Після зміни міток, підказок, діалогових вікон або іншого видимого користувачем тексту виконайте:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
```

Перегляньте разом зміни джерела та відновлені ключі.

## Зміни геометрії та алгоритму

Використовуйте комплектну геометрію зразка під час оптимізації, аналізу щільності, виділення, кадрування,
обробка великих файлів або порівняння вікон перегляду. Він навмисно містить зайві шари
і нерівномірна щільність, тому корисний результат повинен покращити керованість, не приховуючи спотворення,
відкидаючи значущі межі або мовчки видаляючи геометрію, яку зберігає інший алгоритм.

Запис вхідних даних, алгоритму, налаштувань, кількості трикутників, розмірів, дрейфу розмірів, часу, що минув,
і відповідні скріншоти для порівняння. Перевірте як менший фікстур normal-Git, так і, коли
зміна стосується великої або багатошарової геометрії, оригінального світильника Git LFS. Не налаштовуйте алгоритм
тільки до цього приладу. Додайте невеликі синтетичні випадки для конкретного інваріанта або регресії
перевірено.

Перегляньте контрольний список для порівняння [Тестування алгоритму та внесок] (docs/ALGORITHM_TESTING.md).

## Налаштування розробки

1. Установіть 64-розрядну версію Python 3.12 на Windows.
2. Створення та активація віртуального середовища.
3. Встановіть `requirements-dev.txt`.
4. Запустіть `python meshmill.py` для GUI або `python meshmill.py --help` для використання CLI.
5. Запустіть `python -m py_compile meshmill.py` перед надсиланням змін.

Зберігайте приватні сітки, згенеровані виконувані файли, знімки екрана, що містять особисту інформацію, і локальні
створювати каталоги з комітів. Розповсюджувана тестова геометрія належить до `samples/` разом із його
джерело, ліцензія, розміри та метод генерації задокументовані. Нові вихідні файли повинні використовувати
Ідентифікатор SPDX `GPL-3.0-or-later`.

Обріжте кожен скріншот документації до вмісту програми MeshMill. Не включайте
панель завдань, непов’язане вікно chrome, сповіщення, дані облікового запису, приватні шляхи або фон
вміст робочого столу.
