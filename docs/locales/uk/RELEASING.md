# Випуск MeshMill

Конвеєр релізів створює артефакти Windows на серверах Windows, розміщених на GitHub. Кінцеві користувачі отримують
самостійний інсталятор або портативний ZIP і не встановлюйте Python, Node.js або залежності.

Перед створенням оновіть і перевірте вихідні каталоги локалізації:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## До першого публічного релізу

1. Завершити та підтвердити заплановані переклади додатків і документації.
2. Перегляньте GPL і зауваження третіх сторін.
3. Перевірте встановлення, запуск, завантаження STL, оптимізацію, експорт і видалення на чистому
   Обліковий запис Windows або віртуальна машина.
4. Запустіть CI проти `samples/sample-scan.stl`. Перевірте кожен скріншот документації та обріжте
   панель завдань, хром вікон, що не є частиною MeshMill, сповіщення, приватні шляхи, обліковий запис
   деталі та непов’язаний вміст комп’ютера перед публікацією.
5. Налаштуйте локального автора Git у сховищі з адресою без відповідей GitHub облікового запису перед
   перший комміт. Підтвердьте це за допомогою `git config --local --get user.email`.
6. Налаштуйте додаткові секрети підпису Authenticode:
   - `WINDOWS_CERTIFICATE_BASE64`: сертифікат PFX із кодуванням Base64.
   - `WINDOWS_CERTIFICATE_PASSWORD`: пароль PFX.

Без сертифіката підпису згенеровані файли все ще працюють, але Windows SmartScreen може відображати
попередження нерозпізнаного видавця. Не описуйте непідписані збірки як підписані чи надійні.

## Оригінал сканування та Git LFS

`samples/original-scan.stl` відстежується через Git LFS, оскільки він перевищує звичайні 100 МіБ для GitHub
обмеження файлів. Перед першим комітом перевірте:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

Фільтр має бути `lfs`, а ідентифікатор об’єкта вказівника має відповідати `samples/SHA256SUMS.txt`. Звільнення
робочий процес перевіряє вміст LFS і публікує оригінальний STL як окремий випуск. CI використовує
менший зразок нормального Git і не завантажує об’єкт LFS.

## Протестуйте збірку випуску без публікації

Відкрийте **Дії**, виберіть **Випуск**, виберіть **Запустити робочий процес** і введіть числову версію, наприклад
`0.1.0`. Ручний запуск завантажує артефакти робочого процесу для тестування, але не створює загальнодоступний GitHub
Звільнення.

## Опублікувати випуск

З чистої, перевіреної гілки `main`:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

Тег запускає робочий процес випуску. Це:

1. встановлює закріплені залежності збірки;
2. генерує відповідні метадані версії Windows;
3. будує автономні виконувані файли GUI та CLI;
4. підписує виконувані файли, коли налаштовано секрети підпису;
5. створює програму встановлення Inno Setup для кожного користувача;
6. підписує інсталятор після налаштування;
7. створює портативний файл контрольної суми ZIP і SHA-256;
8. завантажує артефакти робочого процесу;
9. створює GitHub Release для надісланого тегу.

Перевірте програму встановлення та портативний архів на чистій системі Windows перед оголошенням випуску.
Зберігайте джерело, що відповідає кожному розповсюдженому двійковому файлу, доступному під одним тегом випуску.
Переконайтеся, що кнопка GitHub вказує на остаточну URL-адресу загальнодоступного сховища, перш ніж позначати перше
реліз.
