# MeshMill जारी किया जा रहा है

रिलीज़ पाइपलाइन GitHub-होस्टेड Windows धावकों पर Windows कलाकृतियों का निर्माण करती है। अंतिम उपयोगकर्ताओं को प्राप्त होता है
एक स्व-निहित इंस्टॉलर या पोर्टेबल ज़िप और Python, Node.js, या निर्भरताएँ स्थापित न करें।

निर्माण से पहले, स्थानीयकरण स्रोत कैटलॉग को ताज़ा और मान्य करें:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## पहली सार्वजनिक रिलीज़ से पहले

1. नियोजित एप्लिकेशन और दस्तावेज़ीकरण अनुवादों को समाप्त करें और मान्य करें।
2. जीपीएल और तीसरे पक्ष के नोटिस की समीक्षा करें।
3. क्लीन पर इंस्टॉलेशन, लॉन्च, STL लोडिंग, ऑप्टिमाइज़ेशन, एक्सपोर्ट और अनइंस्टॉलेशन का परीक्षण करें
   Windows खाता या वर्चुअल मशीन।
4. `samples/sample-scan.stl` के विरुद्ध CI चलाएँ। प्रत्येक दस्तावेज़ स्क्रीनशॉट का निरीक्षण करें और काट-छाँट करें
   टास्कबार, विंडो क्रोम जो MeshMill का हिस्सा नहीं है, सूचनाएं, निजी पथ, खाता
   प्रकाशन से पहले विवरण और असंबद्ध डेस्कटॉप सामग्री।
5. रिपॉजिटरी-स्थानीय Git लेखक को खाते के GitHub नो-रिप्लाई पते से पहले कॉन्फ़िगर करें
   पहले प्रतिबद्ध. `git config --local --get user.email` से इसकी पुष्टि करें।
6. वैकल्पिक ऑथेंटिकोड हस्ताक्षर रहस्य कॉन्फ़िगर करें:
   - `WINDOWS_CERTIFICATE_BASE64`: बेस64-एन्कोडेड PFX प्रमाणपत्र।
   - `WINDOWS_CERTIFICATE_PASSWORD`: पीएफएक्स पासवर्ड।

हस्ताक्षर प्रमाणपत्र के बिना, जेनरेट की गई फ़ाइलें अभी भी काम करती हैं, लेकिन Windows स्मार्टस्क्रीन दिखाई दे सकती है
एक अज्ञात-प्रकाशक चेतावनी. अहस्ताक्षरित बिल्ड को हस्ताक्षरित या विश्वसनीय के रूप में वर्णित न करें।

## मूल स्कैन और Git LFS

`samples/original-scan.stl` को Git LFS के माध्यम से ट्रैक किया जाता है क्योंकि यह GitHub के सामान्य 100 MiB से अधिक है
फ़ाइल सीमा. पहली प्रतिबद्धता से पहले, सत्यापित करें:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

फ़िल्टर `lfs` होना चाहिए, और पॉइंटर ऑब्जेक्ट आईडी `samples/SHA256SUMS.txt` से मेल खाना चाहिए। रिहाई
वर्कफ़्लो LFS सामग्री की जाँच करता है और मूल STL को एक अलग रिलीज़ संपत्ति के रूप में प्रकाशित करता है। सीआई का उपयोग करता है
छोटा सामान्य-Git नमूना और LFS ऑब्जेक्ट डाउनलोड नहीं करता है।

## प्रकाशन के बिना रिलीज़ बिल्ड का परीक्षण करें

**क्रियाएँ** खोलें, **रिलीज़** चुनें, **वर्कफ़्लो चलाएँ** चुनें, और एक संख्यात्मक संस्करण दर्ज करें जैसे कि
`0.1.0`. मैन्युअल रन परीक्षण के लिए वर्कफ़्लो कलाकृतियों को अपलोड करता है लेकिन सार्वजनिक GitHub नहीं बनाता है
रिहाई.

## एक विज्ञप्ति प्रकाशित करें

एक स्वच्छ, समीक्षित `main` शाखा से:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

टैग रिलीज़ वर्कफ़्लो शुरू करता है। यह:

1. पिन की गई बिल्ड निर्भरताएँ स्थापित करता है;
2. मिलान Windows संस्करण मेटाडेटा उत्पन्न करता है;
3. स्व-निहित जीयूआई और सीएलआई निष्पादन योग्य बनाता है;
4. जब हस्ताक्षर रहस्य कॉन्फ़िगर किए जाते हैं तो निष्पादनयोग्य पर हस्ताक्षर करता है;
5. प्रति-उपयोगकर्ता इनो सेटअप इंस्टॉलर बनाता है;
6. कॉन्फ़िगर होने पर इंस्टॉलर पर हस्ताक्षर करता है;
7. पोर्टेबल ज़िप और SHA-256 चेकसम फ़ाइल बनाता है;
8. वर्कफ़्लो कलाकृतियाँ अपलोड करता है;
9. पुश किए गए टैग के लिए GitHub रिलीज़ बनाता है।

रिलीज़ की घोषणा करने से पहले एक साफ़ Windows सिस्टम पर इंस्टॉलर और पोर्टेबल संग्रह को सत्यापित करें।
स्रोत को समान रिलीज़ टैग के अंतर्गत उपलब्ध प्रत्येक वितरित बाइनरी के अनुरूप रखें।
पुष्टि करें कि GitHub बटन पहले टैग करने से पहले अंतिम सार्वजनिक रिपॉजिटरी URL को इंगित करता है
रिहाई.
