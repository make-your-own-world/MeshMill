# MeshMill جاری کرنا

مستحکم ریلیز پائپ لائن GitHub کے میزبان ونڈوز رنرز پر ونڈوز کے نمونے بناتی ہے۔ ایک الگ (Windows) (Windows)
دستی ورک فلو غیر دستخط شدہ لینکس x86-64 اور میکوس انٹیل/ایپل سلکان کے پیش نظارہ مقامی پر بناتا ہے (Linux) (macOS)
GitHub کی میزبانی کرنے والے رنرز۔ آخری صارفین Python، Node.js، یا انحصار کو انسٹال نہیں کرتے ہیں۔

بنانے سے پہلے، لوکلائزیشن سورس کیٹلاگ کو ریفریش اور درست کریں:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## پہلی عوامی ریلیز سے پہلے

1. منصوبہ بند ایپلیکیشن اور دستاویزات کے تراجم کو مکمل اور درست کریں۔
2. GPL اور فریق ثالث کے نوٹسز کا جائزہ لیں۔
3. ٹیسٹ انسٹالیشن، لانچ، STL لوڈنگ، آپٹیمائزیشن، ایکسپورٹ، اور ان انسٹالیشن کلین پر
   Windows اکاؤنٹ یا ورچوئل مشین۔
4. `samples/sample-scan.stl` کے خلاف CI چلائیں۔ ہر دستاویزی اسکرین شاٹ کا معائنہ کریں اور تراشیں۔
   ٹاسک بار، ونڈو کروم جو MeshMill کا حصہ نہیں ہے، اطلاعات، نجی راستے، اکاؤنٹ
   شائع کرنے سے پہلے تفصیلات، اور غیر متعلقہ ڈیسک ٹاپ مواد۔
5. ریپوزٹری-لوکل گٹ مصنف کو اکاؤنٹ کے GitHub بغیر جوابی پتے کے ساتھ ترتیب دیں
   سب سے پہلے عزم. `git config --local --get user.email` کے ساتھ اس کی تصدیق کریں۔
6. اختیاری مستند کوڈ پر دستخط کرنے کے راز کو ترتیب دیں:
   - `WINDOWS_CERTIFICATE_BASE64`: Base64-encoded PFX سرٹیفکیٹ۔
   - `WINDOWS_CERTIFICATE_PASSWORD`: PFX پاس ورڈ۔

دستخطی سرٹیفکیٹ کے بغیر، تیار کردہ فائلیں اب بھی کام کرتی ہیں، لیکن Windows SmartScreen دکھا سکتا ہے
ایک غیر تسلیم شدہ پبلشر کی وارننگ۔ غیر دستخط شدہ تعمیرات کو دستخط شدہ یا قابل اعتماد کے طور پر بیان نہ کریں۔

## اصل اسکین اور Git LFS

`samples/original-scan.stl` کو Git LFS کے ذریعے ٹریک کیا جاتا ہے کیونکہ یہ GitHub کے نارمل 100 MiB سے زیادہ ہے۔
فائل کی حد پہلی کمٹ سے پہلے، تصدیق کریں:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

فلٹر `lfs` ہونا چاہیے، اور پوائنٹر آبجیکٹ ID `samples/SHA256SUMS.txt` سے مماثل ہونا چاہیے۔ رہائی
ورک فلو LFS مواد کو چیک کرتا ہے اور اصل STL کو علیحدہ ریلیز اثاثہ کے طور پر شائع کرتا ہے۔ CI استعمال کرتا ہے۔
چھوٹا نارمل-گٹ نمونہ اور LFS آبجیکٹ کو ڈاؤن لوڈ نہیں کرتا ہے۔

## ریلیز شائع کریں۔

ایک صاف، جائزہ لیا `main` برانچ سے:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

ٹیگ ریلیز ورک فلو کو شروع کرتا ہے۔ یہ:

1. پن کی تعمیر کے انحصار کو انسٹال کرتا ہے؛
2. مماثل Windows ورژن میٹا ڈیٹا تیار کرتا ہے۔
3. خود ساختہ GUI اور CLI ایگزیکیوٹیبل بناتا ہے۔
4. جب دستخط کرنے کے راز کو ترتیب دیا جاتا ہے تو عمل درآمد پر دستخط کرتا ہے۔
5. فی صارف Inno سیٹ اپ انسٹالر بناتا ہے۔
6. کنفیگر ہونے پر انسٹالر پر دستخط کرتا ہے۔
7. پورٹیبل زپ اور SHA-256 چیکسم فائل بناتا ہے۔
8. ورک فلو نمونے اپ لوڈ کرتا ہے؛
9. Pushed ٹیگ کے لیے GitHub ریلیز تخلیق کرتا ہے۔

ریلیز کا اعلان کرنے سے پہلے صاف Windows سسٹم پر انسٹالر اور پورٹیبل آرکائیو کی تصدیق کریں۔
ایک ہی ریلیز ٹیگ کے تحت دستیاب ہر تقسیم شدہ بائنری کے مطابق ذریعہ رکھیں۔
تصدیق کریں کہ پہلے کو ٹیگ کرنے سے پہلے GitHub بٹن حتمی عوامی ذخیرہ URL کی طرف اشارہ کرتا ہے۔
رہائی
