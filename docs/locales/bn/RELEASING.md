# MeshMill প্রকাশ করা হচ্ছে

রিলিজ পাইপলাইন GitHub-হোস্ট করা Windows রানারগুলিতে Windows শিল্পকর্ম তৈরি করে। শেষ ব্যবহারকারীদের গ্রহণ
একটি স্বয়ংসম্পূর্ণ ইনস্টলার বা পোর্টেবল ZIP এবং Python, Node.js, বা নির্ভরতা ইনস্টল করবেন না।

নির্মাণের আগে, স্থানীয়করণ উত্স ক্যাটালগগুলি রিফ্রেশ এবং যাচাই করুন:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## প্রথম প্রকাশের আগে

1. পরিকল্পিত অ্যাপ্লিকেশন এবং ডকুমেন্টেশন অনুবাদগুলি শেষ করুন এবং যাচাই করুন।
2. GPL এবং তৃতীয় পক্ষের বিজ্ঞপ্তি পর্যালোচনা করুন।
3. পরীক্ষা ইনস্টলেশন, লঞ্চ, STL লোডিং, অপ্টিমাইজেশান, রপ্তানি, এবং একটি পরিষ্কার উপর আনইনস্টলেশন
   Windows অ্যাকাউন্ট বা ভার্চুয়াল মেশিন।
4. `samples/sample-scan.stl` এর বিপরীতে CI চালান। প্রতিটি ডকুমেন্টেশন স্ক্রিনশট পরিদর্শন করুন এবং ক্রপ আউট করুন
   টাস্কবার, উইন্ডো ক্রোম যা MeshMill এর অংশ নয়, বিজ্ঞপ্তি, ব্যক্তিগত পথ, অ্যাকাউন্ট
   বিশদ বিবরণ, এবং প্রকাশের আগে অসম্পর্কিত ডেস্কটপ সামগ্রী।
5. রিপোজিটরি-স্থানীয় গিট লেখককে অ্যাকাউন্টের GitHub নো-রিপ্লাই ঠিকানা দিয়ে কনফিগার করুন
   প্রথম প্রতিশ্রুতি `git config --local --get user.email` দিয়ে এটি নিশ্চিত করুন।
6. ঐচ্ছিক প্রমাণীকরণ সাইনিং গোপনীয়তা কনফিগার করুন:
   - `WINDOWS_CERTIFICATE_BASE64`: Base64-এনকোডেড PFX শংসাপত্র।
   - `WINDOWS_CERTIFICATE_PASSWORD`: PFX পাসওয়ার্ড।

একটি স্বাক্ষর শংসাপত্র ছাড়া, তৈরি করা ফাইলগুলি এখনও কাজ করে, কিন্তু Windows স্মার্টস্ক্রিন দেখাতে পারে
একটি অচেনা-প্রকাশক সতর্কতা। স্বাক্ষরবিহীন বিল্ডগুলিকে স্বাক্ষরিত বা বিশ্বস্ত হিসাবে বর্ণনা করবেন না।

## আসল স্ক্যান এবং Git LFS

`samples/original-scan.stl` Git LFS এর মাধ্যমে ট্র্যাক করা হয়েছে কারণ এটি GitHub এর স্বাভাবিক 100 MiB ছাড়িয়ে গেছে
ফাইলের সীমা। প্রথম কমিট করার আগে, যাচাই করুন:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

ফিল্টারটি অবশ্যই `lfs` হতে হবে এবং পয়েন্টার অবজেক্ট আইডি অবশ্যই `samples/SHA256SUMS.txt` এর সাথে মেলে। মুক্তি
ওয়ার্কফ্লো LFS বিষয়বস্তু পরীক্ষা করে এবং আসল STL একটি পৃথক রিলিজ সম্পদ হিসাবে প্রকাশ করে। সিআই ব্যবহার করে
ছোট সাধারণ-গিট নমুনা এবং LFS অবজেক্ট ডাউনলোড করে না।

## প্রকাশ না করে একটি রিলিজ বিল্ড পরীক্ষা করুন

**ক্রিয়া** খুলুন, **রিলিজ** নির্বাচন করুন, **ওয়ার্কফ্লো চালান** চয়ন করুন এবং একটি সংখ্যাসূচক সংস্করণ লিখুন যেমন
`0.1.0`. একটি ম্যানুয়াল রান পরীক্ষার জন্য ওয়ার্কফ্লো আর্টিফ্যাক্ট আপলোড করে কিন্তু একটি সর্বজনীন GitHub তৈরি করে না
মুক্তি।

## একটি রিলিজ প্রকাশ করুন

একটি পরিষ্কার, পর্যালোচনা করা `main` শাখা থেকে:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

ট্যাগটি রিলিজ ওয়ার্কফ্লো শুরু করে। এটা:

1. পিন করা বিল্ড নির্ভরতা ইনস্টল করে;
2. ম্যাচিং Windows সংস্করণ মেটাডেটা তৈরি করে;
3. স্বয়ংসম্পূর্ণ GUI এবং CLI এক্সিকিউটেবল তৈরি করে;
4. সাইনিং সিক্রেট কনফিগার করার সময় এক্সিকিউটেবলে সাইন ইন করে;
5. প্রতি-ব্যবহারকারী ইনো সেটআপ ইনস্টলার তৈরি করে;
6. কনফিগার করা হলে ইনস্টলারকে সাইন ইন করে;
7. পোর্টেবল ZIP এবং SHA-256 চেকসাম ফাইল তৈরি করে;
8. ওয়ার্কফ্লো আর্টিফ্যাক্ট আপলোড করে;
9. পুশ ট্যাগের জন্য GitHub রিলিজ তৈরি করে।

রিলিজ ঘোষণা করার আগে একটি পরিষ্কার Windows সিস্টেমে ইনস্টলার এবং পোর্টেবল সংরক্ষণাগার যাচাই করুন।
একই রিলিজ ট্যাগের অধীনে উপলব্ধ প্রতিটি বিতরণ করা বাইনারির সাথে সংশ্লিষ্ট উৎস রাখুন।
নিশ্চিত করুন যে প্রথমটি ট্যাগ করার আগে GitHub বোতামটি চূড়ান্ত সর্বজনীন সংগ্রহস্থলের URL এর দিকে নির্দেশ করে
মুক্তি
