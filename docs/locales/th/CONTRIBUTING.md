# มีส่วนร่วม

ยินดีมีส่วนร่วมผ่านประเด็นต่างๆ และดึงคำขอ

## ขอบเขตโครงการ

MeshMill ทำให้ไฟล์ Mesh ขนาดใหญ่ หนาแน่น หรือยากสามารถจัดการได้สำหรับการแก้ไขดาวน์สตรีมและ
ขั้นตอนการผลิต การมีส่วนร่วมควรปรับปรุงการตรวจสอบรูปทรงเรขาคณิต ความหนาแน่นของตาข่ายและจุด
การจัดการ, การเพิ่มประสิทธิภาพ, การเลือก, การครอบตัด, การล้างข้อมูล, การตรวจสอบความถูกต้อง, การแลกเปลี่ยน STL, ประสิทธิภาพ,
หรือการประสานงานการดำเนินงานเหล่านั้น

โครงการนี้ไม่รวมถึงการสร้างแบบจำลองทั่วไป การแกะสลัก การระบายสี แอนิเมชัน การเรนเดอร์
การจัดองค์ประกอบฉาก วัสดุ อุปกรณ์ หรือระบบการสร้างเนื้อหาอื่นๆ ข้อเสนอที่แนะนำ
คุณสมบัติเหล่านั้นอยู่นอกขอบเขตของโครงการ

คุณสมบัติใหม่ควรให้ความสำคัญกับแอปพลิเคชัน รักษาขั้นตอนการทำงานโดยตรงที่เปลี่ยนแหล่งที่มา
เรขาคณิตให้เป็น mesh ที่สามารถจัดการได้ และหลีกเลี่ยงการเปลี่ยนส่วนควบคุมที่รองรับเป็นการแก้ไขทั่วไป
สิ่งแวดล้อม

## รองรับหลายภาษา

ข้อความต้นฉบับ UI ภาษาอังกฤษถูกเก็บไว้ใน `locales/en-US.json` ข้อมูลเมตาของสถานที่ถูกเก็บไว้ใน
`locales/manifest.json`. แค็ตตาล็อก UI ที่แปลจะใช้คีย์ที่เสถียรและชื่อไฟล์เดียวกัน
`<locale>.json`. เอกสารที่แปลจะใช้ชื่อไฟล์รูทที่ตรงกันด้านล่าง
`docs/locales/<locale>/`.

การแปลเริ่มแรกด้วยบริการแปลด้วยเครื่องภายนอกและรับ
การตรวจสอบโครงสร้างอัตโนมัติ กระบวนการนั้นไม่สามารถรับประกันได้ว่าเป็นธรรมชาติ แม่นยำทางเทคนิค หรือ
ภาษาที่ถูกต้องตามบริบท เราสนับสนุนให้เจ้าของภาษาตรวจสอบและแก้ไข UI ที่แปล
ข้อความและเอกสารประกอบ การแก้ไขคำแปลควรคงคีย์แค็ตตาล็อก ตัวยึดตำแหน่ง
คำสั่ง ลิงค์ การวัด ชื่อผลิตภัณฑ์ และโครงสร้าง Markdown

หลังจากเปลี่ยนป้ายกำกับ คำแนะนำเครื่องมือ กล่องโต้ตอบ หรือข้อความอื่นที่ผู้ใช้มองเห็น ให้รัน:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
```

ตรวจสอบการเปลี่ยนแปลงแหล่งที่มาและคีย์ที่สร้างใหม่ร่วมกัน

## การเปลี่ยนแปลงเรขาคณิตและอัลกอริทึม

ใช้เรขาคณิตตัวอย่างที่รวมมาเมื่อเปลี่ยนแปลงการปรับให้เหมาะสม การวิเคราะห์ความหนาแน่น การเลือก การครอบตัด
การจัดการไฟล์ขนาดใหญ่ หรือพฤติกรรมการเปรียบเทียบวิวพอร์ต โดยเจตนามีเลเยอร์ที่ซ้ำซ้อน
และความหนาแน่นไม่สม่ำเสมอ ดังนั้นผลลัพธ์ที่เป็นประโยชน์ควรปรับปรุงความสามารถในการจัดการโดยไม่ปิดบังการบิดเบือน
ละทิ้งขอบเขตที่มีความหมาย หรือลบรูปทรงเรขาคณิตที่อัลกอริธึมอื่นเก็บรักษาไว้อย่างเงียบๆ

บันทึกอินพุต, อัลกอริธึม, การตั้งค่า, จำนวนสามเหลี่ยม, มิติ, การเลื่อนของมิติ, เวลาที่ผ่านไป,
และภาพหน้าจอที่เกี่ยวข้องสำหรับการเปรียบเทียบ ทดสอบทั้งฟิกซ์เจอร์ Git ปกติที่เล็กกว่าและเมื่อ
การเปลี่ยนแปลงเกี่ยวข้องกับรูปทรงเรขาคณิตขนาดใหญ่หรือแบบชั้น ฟิกซ์เจอร์ Git LFS ดั้งเดิม อย่าปรับแต่งอัลกอริทึม
ให้กับฟิกซ์เจอร์นี้เพียงอย่างเดียว เพิ่มกรณีสังเคราะห์ขนาดเล็กสำหรับค่าคงที่หรือการถดถอยเฉพาะ
ทดสอบแล้ว

ดู [การทดสอบอัลกอริทึมและการสนับสนุน](docs/ALGORITHM_TESTING.md) สำหรับรายการตรวจสอบการเปรียบเทียบ

## การตั้งค่าการพัฒนา

1. ติดตั้ง Python 3.12 64 บิตบน Windows
2. สร้างและเปิดใช้งานสภาพแวดล้อมเสมือน
3. ติดตั้ง `requirements-dev.txt`
4. เรียกใช้ `python meshmill.py` สำหรับ GUI หรือ `python meshmill.py --help` สำหรับการใช้งาน CLI
5. รัน `python -m py_compile meshmill.py` ก่อนส่งการเปลี่ยนแปลง

เก็บตาข่ายส่วนตัว ไฟล์ปฏิบัติการที่สร้างขึ้น ภาพหน้าจอที่มีข้อมูลส่วนตัว และในเครื่อง
สร้างไดเร็กทอรีออกจากการคอมมิต เรขาคณิตทดสอบแบบแจกจ่ายต่อได้อยู่ภายใต้ `samples/` พร้อมด้วย
แหล่งที่มา ใบอนุญาต ขนาด และวิธีการสร้างเอกสาร ไฟล์ต้นฉบับใหม่ควรใช้นามสกุล
ตัวระบุ SPDX `GPL-3.0-or-later`

ครอบตัดทุกภาพหน้าจอเอกสารเป็นเนื้อหาแอปพลิเคชัน MeshMill ไม่ต้องรวม
แถบงาน, หน้าต่าง Chrome ที่ไม่เกี่ยวข้อง, การแจ้งเตือน, รายละเอียดบัญชี, เส้นทางส่วนตัว หรือพื้นหลัง
เนื้อหาบนเดสก์ท็อป
