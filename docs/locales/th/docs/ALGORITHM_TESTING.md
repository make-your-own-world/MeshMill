# การทดสอบอัลกอริทึมและการสนับสนุน

อัลกอริธึม MeshMill ควรทำให้เรขาคณิตที่ยากสามารถจัดการได้ในขณะที่ยังคงมองเห็นเอฟเฟกต์ได้
วัดได้และย้อนกลับได้ก่อนที่จะใช้ผลลัพธ์

## การแข่งขันอ้างอิง

ใช้เรขาคณิตตัวอย่างคอมโพสิตทั้งสองเวอร์ชันที่รวมกลุ่ม:

- `samples/sample-scan.stl` เป็นฟิกซ์เจอร์ Git ปกติที่เล็กกว่าสำหรับการพัฒนาตามปกติแบบอัตโนมัติ
  การตรวจสอบและการเรียนรู้การควบคุม
- `samples/original-scan.stl` เป็นฟิกซ์เจอร์ Git LFS เต็มรูปแบบสำหรับลักษณะการทำงานของไฟล์ขนาดใหญ่ เลเยอร์ซ้ำซ้อน
  ความหนาแน่นไม่สม่ำเสมอ การทับซ้อนกัน และประสิทธิภาพการทำงาน

บริเวณที่ซ้ำซ้อนและหนาแน่นเป็นลักษณะการทดสอบโดยเจตนา การทดสอบอาจกำหนดเป้าหมายไปที่พวกเขา แต่
ไม่ควรถือว่าทุกพื้นผิวที่ทับซ้อนกันเป็นแบบใช้แล้วทิ้ง เพิ่มตาข่ายสังเคราะห์ขนาดกะทัดรัดเมื่อ
การเปลี่ยนแปลงจำเป็นต้องมีขอบเขต ความโค้ง โทโพโลยี ความหนาแน่น หรือค่าคงที่ที่ทับซ้อนกันที่ทราบ

## รายการตรวจสอบการเปรียบเทียบ

สำหรับการเปลี่ยนแปลงอัลกอริทึมหรือพารามิเตอร์ ให้บันทึก:

- เวอร์ชัน MeshMill หรือคอมมิต;
- การติดตั้งอินพุตและเช็คซัม
- อัลกอริธึม การตั้งค่าคุณภาพล่วงหน้า เป้าหมาย และการตั้งค่าขั้นสูง
- จำนวนสามเหลี่ยมและจุดยอดดั้งเดิมและผลลัพธ์
- เปอร์เซ็นต์การลด ขนาด และการเบี่ยงเบนของมิติ
- เวลาที่ผ่านไปและหน่วยความจำสูงสุดเมื่อประสิทธิภาพเกี่ยวข้อง
- ภาพหน้าจอจากมุมมองและโหมดการแสดงผลที่บันทึกไว้เดียวกัน
- ขอบเขตที่มองเห็นได้ หลุม การแยกตัวเอง การทับซ้อนกัน หรือการบิดเบือน
- ไม่ว่าผลลัพธ์จะมาจากการดำเนินการทั้งเมชหรือการเลือกเท่านั้น

เปรียบเทียบกับพฤติกรรมปัจจุบันที่เป้าหมายเดียวกัน ไม่เพียงแต่กับค่าที่ตั้งล่วงหน้าอื่นด้วย a
จำนวนเอาต์พุตที่แตกต่างกัน ตรวจสอบการแรเงา ความหนาแน่น โครงร่าง และจุดยอดตามความเหมาะสม

## คำแนะนำการยอมรับ

การเปลี่ยนแปลงการปรับให้เหมาะสมควรหลีกเลี่ยงการเปลี่ยนแปลงมิติที่ไม่คาดคิด การกลับด้านพื้นผิวที่ชัดเจน
รอยแตกระหว่างภูมิภาคที่ประมวลผล การสูญเสียขอบเขตที่มีความหมาย และการถดถอยคุณภาพขนาดใหญ่ที่
จำนวนเอาต์พุตที่คล้ายกัน การเปลี่ยนแปลงที่เน้นความหนาแน่นควรแสดงให้เห็นว่าความเข้มข้นที่ถูกลบออกมีผล
ไม่มีความโค้งหรือโทโพโลยีที่เป็นประโยชน์

ผลลัพธ์ประสิทธิภาพควรระบุโปรเซสเซอร์ ความจุหน่วยความจำ ฮาร์ดแวร์กราฟิก การทำงาน
ระบบ ขนาดอินพุต และข้อมูลถูกแคชไว้แล้วหรือไม่ การตรวจสอบโครงสร้างและภาพหน้าจอ
สนับสนุนการตรวจสอบ แต่อย่าแทนที่การตรวจสอบโดยผู้ร่วมให้ข้อมูลที่คุ้นเคยกับเรขาคณิตของแหล่งที่มา

## การทดสอบการถดถอย

ชอบการทดสอบที่กำหนดโดยมีค่าความคลาดเคลื่อนที่ชัดเจน ทำให้การติดตั้งใหม่มีขนาดเล็กพอสำหรับ Git ปกติ
บันทึกแหล่งที่มาและใบอนุญาต และใช้เรขาคณิตสังเคราะห์เมื่อไม่จำเป็นต้องใช้ข้อมูลต้นฉบับจริง
การทดสอบควรครอบคลุมถึงการยกเลิกและการคืนค่าสถานะเมื่อการดำเนินการสามารถปรับเปลี่ยนรูปทรงได้
