# โรดแมป MeshMill

## การสนับสนุนแพลตฟอร์ม

Windows เป็นแพลตฟอร์มแพ็กเกจเริ่มต้น สถาปัตยกรรมแอปพลิเคชันและรูปแบบตาข่ายคือ
ข้ามแพลตฟอร์มและการเปิดตัวในอนาคตควรเพิ่มแพ็คเกจ Linux และ macOS ดั้งเดิม งานแพลตฟอร์ม
รวมถึงบรรจุภัณฑ์ การรวมแอปพลิเคชัน การวัดฮาร์ดแวร์ พฤติกรรมของระบบไฟล์ และการทำงานอัตโนมัติ
ปล่อยการทดสอบโดยรักษาโปรเจ็กต์เดียวกันและเวิร์กโฟลว์ STL ไว้ในทุกระบบที่รองรับ

- ตรวจสอบแพ็คเกจการแสดงตัวอย่าง Linux x86-64 ทั่วทั้งดิสทริบิวชัน สภาพแวดล้อมเดสก์ท็อป และจอแสดงผล
  เซิร์ฟเวอร์และไดรเวอร์ GPU ก่อนที่จะโปรโมตให้เสถียร
- ตรวจสอบ macOS Apple Silicon และแพ็คเกจตัวอย่าง x86-64 บนฮาร์ดแวร์จริง จากนั้นเพิ่ม Developer
  การลงนามและรับรองเอกสารประจำตัวก่อนที่จะส่งเสริมให้มีเสถียรภาพ
- เพิ่มผู้ให้บริการตัววัด CPU หน่วยความจำ และ GPU แบบเนทีฟแพลตฟอร์ม ด้านหลังอินเทอร์เฟซที่ใช้ร่วมกัน
- เก็บการตั้งค่าที่บันทึกไว้ การแมปคีย์บอร์ด ลักษณะการทำงานของบรรทัดคำสั่ง และข้อมูลโปรเจ็กต์ไว้พกพาได้

แผนงานนี้จะบันทึกงานที่วางแผนไว้ ไม่ได้อธิบายคุณสมบัติในรุ่นปัจจุบัน

## ขอบเขต

MeshMill จัดการเรขาคณิต ความหนาแน่นของตาข่าย ความหนาแน่นของจุด การเพิ่มประสิทธิภาพ การล้างข้อมูล การตรวจสอบ และ STL
การแลกเปลี่ยนไฟล์เมชที่มีขนาดใหญ่หรือหนักมากยังคงมีประโยชน์ในเวิร์กโฟลว์การแก้ไขดาวน์สตรีม

การสร้างแบบจำลองวัตถุประสงค์ทั่วไป การแกะสลัก การระบายสี การสร้างภาพเคลื่อนไหว การเรนเดอร์ การจัดองค์ประกอบฉาก วัสดุ
เสื้อผ้าและระบบการสร้างเนื้อหาอื่นๆ อยู่นอกแผนงานนี้ ใช้การสังเคราะห์แบบกระจาย
ไปยังการดำเนินการจัดการตาข่ายของ MeshMill และไม่ได้ขยายผลิตภัณฑ์ไปสู่โปรแกรมแก้ไขทั่วไป

## เรขาคณิตอ้างอิง

คอมโพสิตเมชแบบรวมเป็นฟิกซ์เจอร์การพัฒนาทั่วไปสำหรับอัลกอริธึมและแผนงานปัจจุบัน
ทำงาน ชั้นที่ซ้ำซ้อนโดยเจตนาและความหนาแน่นที่ไม่สม่ำเสมอรองรับการเปรียบเทียบที่สามารถทำซ้ำได้
คุณภาพการลด การวิเคราะห์ความหนาแน่น การจัดการที่ทับซ้อนกัน การดำเนินงานระดับภูมิภาค การประมวลผลนอกระบบ
และการสังเคราะห์ในอนาคต การใช้แผนงานควรรายงานผลลัพธ์เทียบกับฟิกซ์เจอร์นี้และขนาดเล็ก
Regression Meshes ที่สร้างขึ้นโดยเฉพาะ แทนที่จะปรับพฤติกรรมให้เหมาะสมสำหรับโมเดลเดียวเพียงอย่างเดียว

## พื้นที่ทำงาน Multi-STL และการสังเคราะห์ทางสถิติ

พื้นที่ทำงานควรยอมรับอินพุต STL หลายรายการเป็นออบเจ็กต์ต้นทางที่แยกจากกันและมองเห็นได้โดยอิสระ
MeshMill ควรจัดตำแหน่งแหล่งที่มาเหล่านั้น วัดข้อตกลงทางเรขาคณิต และสังเคราะห์แหล่งที่มาที่ใช้งานได้
ตาข่ายโดยไม่รักษาพื้นผิวภายในที่ซ้ำกันหรือรูปทรงเรขาคณิตที่ทับซ้อนกันซ้ำ ๆ

พฤติกรรมที่วางแผนไว้:

- เพิ่ม ลบ ซ่อน แยก เรียงลำดับใหม่ และตรวจสอบแหล่งที่มาของ STL หลายแหล่งในพื้นที่ทำงานเดียว
- รักษาเอกลักษณ์ของแหล่งที่มา หน่วย การแปลง ขอบเขต ความละเอียด และประวัติการดำเนินการ
- ให้การลงทะเบียนอัตโนมัติพร้อมการควบคุมการจัดตำแหน่งด้วยตนเองและคุณภาพความพอดีที่วัดได้
- แบ่งแหล่งที่มาลงในพื้นที่เชิงพื้นที่ก่อนการเปรียบเทียบ เพื่อให้อินพุตขนาดใหญ่ยังคงมีขอบเขตอยู่
- วิเคราะห์อัตราการเข้าพัก ระยะห่างพื้นผิวที่ใกล้ที่สุด ข้อตกลงปกติ ความหนาแน่นของท้องถิ่น ความแปรปรวน และ
  จำนวนการสังเกตข้ามภูมิภาคที่ทับซ้อนกัน
- จำแนกพื้นผิวที่ตรงกัน พื้นผิวที่ขัดแย้งกัน สัญญาณรบกวน ช่องว่าง และรูปทรงเรขาคณิตที่เป็นเอกลักษณ์
- รวมพื้นผิวที่ตกลงกันทางสถิติไว้เป็นพื้นผิวตัวแทนพร้อมบันทึกไว้
  ความมั่นใจแทนที่จะซ้อนสามเหลี่ยมที่ซ้ำกัน
- ลบรูปทรงเรขาคณิตที่ปิดล้อม บังเอิญ และใช้ร่วมกันซึ่งไม่มีส่วนให้รายละเอียดรูปร่างภายนอก
- รักษาเรขาคณิตของแหล่งที่มาที่ไม่ทับซ้อนกันและเปิดเผยขอบเขตที่คลุมเครือเพื่อการตรวจสอบด้วยภาพ
- อนุญาตให้มีการถ่วงน้ำหนักต่อแหล่งที่มาและต่อภูมิภาคเมื่อการสแกนหนึ่งครั้งมีความชัดเจนหรือมีรายละเอียดมากขึ้น
- ตรวจสอบความกันน้ำ ขอบเขต บรรทัดฐาน มิติ และโทโพโลยีหลังการสังเคราะห์
- แหล่งที่มาของบันทึกและพารามิเตอร์การสังเคราะห์เพื่อให้ตาข่ายที่รวมกันสามารถทำซ้ำได้
- ดูตัวอย่างจำนวนสามเหลี่ยมที่คาดหวัง ขอบเขต การทับซ้อนที่ถูกลบออก และการกระจายความเชื่อมั่นก่อนหน้านี้
  กระทำการผลการสังเคราะห์

เวิร์กโฟลว์นี้ควรใช้ดัชนีเชิงพื้นที่นอกคอร์เดียวกันและแบบจำลองหน่วยงานที่วางแผนไว้สำหรับขนาดใหญ่
ตาข่าย การเปรียบเทียบทางสถิติและการรวมข้อมูลที่ทับซ้อนกันควรกระจายทั่วทั้งท้องถิ่นด้วย
หรือโหนด MeshMill ระยะไกล

## การสังเคราะห์แบบกระจาย

คลัสเตอร์ MeshMill ควรประสานงานหลายโหนดที่ทำงานแบบขนานข้ามหลายโหนด
เวิร์กสเตชัน โหนดอาจตรวจสอบ เลือก ลด ตรวจสอบ ซ่อมแซม หรือรวมภูมิภาคที่ได้รับมอบหมายหรือ
หน่วยงาน ผลงานจะยังคงมีเวอร์ชันที่แยกจากกันจนกว่าจะได้รับการตรวจสอบและรวมเข้าด้วยกัน
ลงในเวอร์ชันออบเจ็กต์ที่ใช้ร่วมกัน

ระบบควรรองรับ:

- การสนับสนุนพร้อมกันจากผู้ปฏิบัติงานหลายรายและโหนดอัตโนมัติ
- อินพุต พารามิเตอร์ การขึ้นต่อกัน และเอาท์พุตของหน่วยงานที่กำหนดขึ้น
- การกำหนดเวลาการรับรู้ความสามารถโดยอิงจาก CPU, GPU, หน่วยความจำ, อัลกอริธึม และโหลดปัจจุบัน
- การแบ่งพาร์ติชันของเมช พื้นที่ ผ่านการตรวจสอบ และขั้นตอนการสังเคราะห์โดยคำนึงถึงการพึ่งพาอาศัยกัน
- คิวที่คงทนด้วยการหยุดชั่วคราว ดำเนินการต่อ การยกเลิก ลองใหม่ มอบหมายใหม่ และการกู้คืนความล้มเหลว
- สิ่งประดิษฐ์ที่ระบุถึงเนื้อหาและการตรวจสอบความสมบูรณ์ระหว่างโหนด
- การสังเคราะห์ที่ทำซ้ำได้จากชุดเวอร์ชันที่ยอมรับที่บันทึกไว้
- เวิร์กสเตชันที่เชื่อมต่อแบบออฟไลน์หรือเป็นระยะๆ ซึ่งสามารถซิงโครไนซ์ได้ในภายหลัง
- การดำเนินการแบบโลคอลเป็นอันดับแรกพร้อมการควบคุมโหนดที่เข้าร่วมและข้อมูลโปรเจ็กต์ที่แชร์อย่างชัดเจน

## การทำงานร่วมกันในเวอร์ชัน

ทุกการสนับสนุนควรบันทึกเวอร์ชันออบเจ็กต์หลัก ภูมิภาคหรือหน่วยงานที่เลือก การดำเนินงาน
พารามิเตอร์ ข้อมูลประจำตัวของโหนด การประทับเวลา การขึ้นต่อกัน ผลการตรวจสอบ และการตรวจสอบผลรวมเอาต์พุต

พฤติกรรมการทำงานร่วมกันตามแผน:

- โครงการประกอบด้วยวัตถุ สาขา จุดตรวจสอบ การสนับสนุน และเวอร์ชันสังเคราะห์
- ผู้ร่วมให้ข้อมูลสามารถทำงานจากเวอร์ชันหลักเดียวกันได้โดยไม่ต้องเขียนทับกัน
- การสนับสนุนที่ไม่ทับซ้อนกันสามารถรวมเข้าด้วยกันได้โดยอัตโนมัติหลังจากการตรวจสอบความถูกต้อง
- เรขาคณิตที่ทับซ้อนกันหรือการขึ้นต่อกันที่เข้ากันไม่ได้ทำให้เกิดข้อขัดแย้งที่ชัดเจน
- ข้อขัดแย้งให้การเปรียบเทียบด้วยภาพ ตัวเลือกระดับภูมิภาค การรีบูต การรันซ้ำ และการแก้ไขด้วยตนเอง
- สถานะการตรวจสอบ ได้แก่ รอดำเนินการ ยอมรับ ปฏิเสธ แทนที่ ขัดแย้ง และรวมเข้าด้วยกัน
- รายการการสังเคราะห์ขั้นสุดท้ายระบุทุกการมีส่วนร่วมและการพึ่งพาที่รวมเข้าด้วยกัน

## UI การประสานงาน

แอปพลิเคชันเดสก์ท็อปควรจัดการงานแบบกระจายโดยไม่ต้องใช้บรรทัดคำสั่งแยกต่างหาก
หรือเวิร์กโฟลว์การดูแลเซิร์ฟเวอร์ มุมมองที่วางแผนไว้ได้แก่:

- **โปรเจ็กต์:** ออบเจ็กต์ สาขา เวอร์ชัน ผู้มีส่วนร่วม และสถานะการสังเคราะห์
- **คลัสเตอร์:** เวิร์กสเตชันและโหนดที่เชื่อมต่อ ความสามารถ ความสมบูรณ์ โหลด และการกำหนดปัจจุบัน
- **คิว:** อยู่ระหว่างดำเนินการ ใช้งานอยู่ หยุดชั่วคราว ถูกบล็อก ล้มเหลว และเสร็จสมบูรณ์แล้ว
- **การมีส่วนร่วม:** ผู้เขียน โหนด เวอร์ชันหลัก ภูมิภาคที่ได้รับผลกระทบ พารามิเตอร์ การตรวจสอบ และสถานะการตรวจสอบ
- **เปรียบเทียบ:** มุมมอง 3 มิติที่ซิงโครไนซ์ ความแตกต่างทางเรขาคณิต เมตริก และการตรวจสอบขอบเขต (3D)
- **ข้อขัดแย้ง:** ภูมิภาคที่ทับซ้อนกัน ข้อขัดแย้งในการขึ้นต่อกัน ตัวเลือกการแก้ปัญหา และผลการตรวจสอบ
- **การสังเคราะห์:** กราฟอ้างอิง ความคืบหน้าโดยรวม เวอร์ชันสนับสนุนที่เลือก และผลลัพธ์สุดท้าย
- **ประวัติ:** กราฟสาขา จุดตรวจสอบ การรวม เวอร์ชันสังเคราะห์ และรายการความสามารถในการทำซ้ำ

วิวพอร์ตควรแสดงความเป็นเจ้าของ ภูมิภาคที่ได้รับมอบหมาย งานที่เสร็จสมบูรณ์ การเปลี่ยนแปลงที่รอดำเนินการ ข้อขัดแย้ง
และความแตกต่างของเวอร์ชันโดยไม่ต้องเปลี่ยนเมชพื้นฐาน

## ประสานงานและขนส่ง

ขั้นตอนการออกแบบแรกควรกำหนดขอบเขตของโปรโตคอลก่อนที่จะเลือกการขนส่ง โปรโตคอล
ควรแยกข้อมูลเมตาของการประสานงานออกจากส่วนตาข่ายขนาดใหญ่ รองรับการถ่ายโอนที่ดำเนินการต่อได้ และ
ยังคงใช้งานได้บนเครือข่ายท้องถิ่นโดยไม่มีบัญชีภายนอกหรือบริการที่โฮสต์

แนวคิดการประสานงานที่จำเป็น:

- การเลือกตั้งผู้ประสานงานหรือผู้ประสานงานที่ได้รับการคัดเลือกอย่างชัดเจน
- การค้นพบโหนดและการลงทะเบียนโหนดด้วยตนเอง
- เซสชันการรับรองความถูกต้องและการอนุญาตขอบเขตโครงการ
- สัญญาเช่าและหัวใจสำหรับการเป็นเจ้าของงาน
- การส่งงานแบบเดิมและการยอมรับผลงาน
- การเจรจาเวอร์ชันระหว่างรุ่น MeshMill ที่แตกต่างกัน
- เหตุการณ์ที่มีโครงสร้างสำหรับความคืบหน้า บันทึก การตรวจสอบ ความล้มเหลว และการลองใหม่
- การกู้คืนหลังจากการประสานงาน เวิร์กสเตชัน เครือข่าย หรือโหนดหยุดชะงัก

## ขั้นตอนการจัดส่ง

### เฟส 0: การประมวลผลแบบตาข่ายขนาดใหญ่นอกคอร์

ดัชนี การสตรีม แคช หน่วยงาน และสัญญาความปลอดภัยได้รับการบันทึกไว้ในเอกสาร
[`docs/OUT_OF_CORE.md`](docs/OUT_OF_CORE.md)

- ประมาณจำนวนสามเหลี่ยมและหน่วยความจำในการทำงานก่อนจัดสรรเมชทั้งหมด
- เปิดไฟล์ไบนารี STL ขนาดใหญ่เป็นภาพรวมการนำทางที่มีขอบเขตและสุ่มตัวอย่างเท่าๆ กัน
- แบ่งพาร์ติชันเรขาคณิตที่มีความละเอียดเต็มเป็นลูกบาศก์เชิงพื้นที่โดยมีขอบเขตการทับซ้อนกันตามที่กำหนด
- อ่าน วิเคราะห์ และเพิ่มประสิทธิภาพคิวบ์อิสระพร้อมกันภายใน CPU และขีดจำกัดหน่วยความจำ
- การใช้งานการประมวลผล GPU เกณฑ์มาตรฐานสำหรับขั้นตอนการลด เช่น การประเมินข้อผิดพลาด ตัวเลือก
  การให้คะแนน การสืบค้นเชิงพื้นที่ และการประมวลผลหน่วยงานอิสระ ออฟโหลดเวทีเฉพาะเมื่อเท่านั้น
  ให้ความเร็วแบบ end-to-end ที่วัดได้หรือประโยชน์ของหน่วยความจำ โดยไม่ลดระดับที่กำหนด, mesh
  คุณภาพ การรับประกันโทโพโลยี หรือความเข้ากันได้กับระบบที่ขาด GPU ที่เหมาะสม
- สตรีมระดับวิวพอร์ตแบบหยาบถึงละเอียด แทนที่จะต้องใช้เมชที่สมบูรณ์ในหน่วยความจำ
- วาดสถานะคิวบ์โดยตรงในวิวพอร์ต: เข้าคิว กำลังอ่าน ประมวลผล เสร็จสมบูรณ์ และล้มเหลว
- แสดงความคืบหน้าต่อคิวบ์โดยการเติมแต่ละคิวบ์และคงมุมมองออบเจ็กต์ทั้งหมดในระดับสูง
- ประกอบคิวบ์ที่ประมวลผลด้วยการตรวจสอบขอบเขต การลบซ้ำ และการตั้งค่าที่ทำซ้ำได้
- ขยายตัวกำหนดเวลาคิวบ์โลคัลไปเป็นหน่วยงานการสังเคราะห์แบบกระจายในเฟสต่อๆ ไป

### ระยะที่ 1: มูลนิธิท้องถิ่นตามเวอร์ชัน

- กำหนดออบเจ็กต์ การดำเนินการ การสนับสนุน สาขา และรูปแบบรายการ
- เพิ่มพื้นที่ทำงานหลาย STL พร้อมการมองเห็น การแปลง ข้อมูลเมตา และแหล่งที่มาต่อแหล่งที่มา
- เพิ่มตัวชี้วัดคุณภาพการลงทะเบียนและการจำแนกประเภทที่ทับซ้อนกันเชิงพื้นที่
- สังเคราะห์พื้นผิวที่ตกลงกันทางสถิติในขณะที่ลบเรขาคณิตที่ซ้ำกันและล้อมรอบออก
- เพิ่มการตรวจสอบด้วยภาพเพื่อดูข้อขัดแย้ง ช่องว่าง ความมั่นใจ และเรขาคณิตที่ไม่ซ้ำใครในแหล่งเดียว
- คงไว้ซึ่งประวัติในเครื่องตลอดเซสชันของแอปพลิเคชัน
- เพิ่มการเปรียบเทียบภาพและภูมิภาค
- ทำให้การดำเนินงานมีการกำหนดและทำซ้ำได้อย่างอิสระ

### ระยะที่ 2: โหนดท้องถิ่นที่มีการประสานงาน

- รันโหนดผู้ปฏิบัติงานบนเวิร์กสเตชันเดียว
- เพิ่มการจัดคิว การรายงานความสามารถ การมอบหมายงาน และการยกเลิก
- แสดงโหนดและสถานะของหน่วยงานใน MeshMill UI
- ตรวจสอบการแบ่งพาร์ติชันและการประกอบผลลัพธ์ภายในเครื่อง

### ระยะที่ 3: การสังเคราะห์หลายเวิร์กสเตชัน

- เพิ่มการค้นพบและการลงทะเบียน LAN ที่ได้รับการรับรองความถูกต้อง
- ถ่ายโอนอินพุตและผลลัพธ์การทำงานตามเนื้อหาพร้อมการสนับสนุนเรซูเม่
- ประสานงานการทำงานพร้อมกันบนเวิร์กสเตชันหลายเครื่อง
- กู้คืนการกำหนดหลังจากโหนดหรือเครือข่ายล้มเหลว

### ระยะที่ 4: เวอร์ชันการทำงานร่วมกัน

- เพิ่มผู้ร่วมให้ข้อมูล สาขา สถานะการตรวจสอบ และการอนุญาต
- รวมผลงานที่ไม่ทับซ้อนกัน
- ตรวจจับและแก้ไขข้อขัดแย้งที่ทับซ้อนกันหรือการขึ้นต่อกัน
- สังเคราะห์การสนับสนุนที่เลือกให้เป็นเวอร์ชันออบเจ็กต์ที่ทำซ้ำได้

### ขั้นตอนที่ 5: การแข็งตัวของการผลิต

- เพิ่มการทดสอบความเข้ากันได้ของโปรโตคอลและการจัดการเวอร์ชันผสม
- เพิ่มการทดสอบการตรวจสอบ ความสมบูรณ์ การทุจริต การหยุดชะงัก และการกู้คืน
- การกำหนดเกณฑ์มาตรฐาน การแบ่งพาร์ติชัน การถ่ายโอน การรวม และการสังเคราะห์ประสิทธิภาพ
- การปรับใช้เอกสาร การสำรองข้อมูล การโยกย้าย และการกู้คืนเหตุการณ์
