# ปล่อย MeshMill

ไปป์ไลน์การเปิดตัวจะสร้างสิ่งประดิษฐ์ Windows บนนักวิ่ง Windows ที่โฮสต์โดย GitHub ผู้ใช้ปลายทางได้รับ
ตัวติดตั้งในตัวเองหรือ ZIP แบบพกพา และไม่ติดตั้ง Python, Node.js หรือการอ้างอิง

ก่อนที่จะสร้าง ให้รีเฟรชและตรวจสอบความถูกต้องของแค็ตตาล็อกแหล่งที่มาของการแปล:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## ก่อนออกสู่สาธารณะครั้งแรก

1. เสร็จสิ้นและตรวจสอบความถูกต้องของแอปพลิเคชันที่วางแผนไว้และการแปลเอกสาร
2. ตรวจสอบ GPL และประกาศของบุคคลที่สาม
3. ทดสอบการติดตั้ง เปิดใช้งาน การโหลด STL การเพิ่มประสิทธิภาพ การส่งออก และการถอนการติดตั้งแบบคลีน
   บัญชี Windows หรือเครื่องเสมือน
4. เรียกใช้ CI กับ `samples/sample-scan.stl` ตรวจสอบภาพหน้าจอเอกสารทุกฉบับและครอบตัดออก
   แถบงาน, หน้าต่าง Chrome ที่ไม่ได้เป็นส่วนหนึ่งของ MeshMill, การแจ้งเตือน, เส้นทางส่วนตัว, บัญชี
   รายละเอียดและเนื้อหาเดสก์ท็อปที่ไม่เกี่ยวข้องก่อนเผยแพร่
5. กำหนดค่าผู้เขียน Git ในที่เก็บข้อมูลด้วยที่อยู่ที่ไม่ตอบกลับ GitHub ของบัญชีก่อน
   กระทำครั้งแรก ยืนยันด้วย `git config --local --get user.email`
6. กำหนดค่าความลับในการลงนาม Authenticode ที่เป็นตัวเลือก:
   - `WINDOWS_CERTIFICATE_BASE64`: ใบรับรอง PFX ที่เข้ารหัส Base64
   - `WINDOWS_CERTIFICATE_PASSWORD`: รหัสผ่าน PFX

หากไม่มีใบรับรองการลงนาม ไฟล์ที่สร้างขึ้นจะยังคงใช้งานได้ แต่ Windows SmartScreen อาจแสดงขึ้นมา
คำเตือนของผู้เผยแพร่โฆษณาที่ไม่รู้จัก อย่าอธิบายบิลด์ที่ไม่ได้ลงนามว่าลงนามหรือเชื่อถือได้

## การสแกนต้นฉบับและ Git LFS

`samples/original-scan.stl` ถูกติดตามผ่าน Git LFS เนื่องจากเกิน 100 MiB ปกติของ GitHub
ขีดจำกัดไฟล์ ก่อนคอมมิตครั้งแรก ให้ตรวจสอบ:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

ตัวกรองต้องเป็น `lfs` และ ID อ็อบเจ็กต์ตัวชี้ต้องตรงกับ `samples/SHA256SUMS.txt` การปล่อย
เวิร์กโฟลว์ตรวจสอบเนื้อหา LFS และเผยแพร่ STL ดั้งเดิมเป็นเนื้อหาที่เผยแพร่แยกต่างหาก ซีไอใช้
ตัวอย่าง Git ปกติที่เล็กกว่าและไม่ดาวน์โหลดออบเจ็กต์ LFS

## ทดสอบบิลด์รุ่นโดยไม่ต้องเผยแพร่

เปิด **การกระทำ** เลือก **เผยแพร่** เลือก **เรียกใช้เวิร์กโฟลว์** และป้อนเวอร์ชันตัวเลข เช่น
`0.1.0`. การรันด้วยตนเองจะอัปโหลดสิ่งประดิษฐ์ของเวิร์กโฟลว์สำหรับการทดสอบ แต่ไม่ได้สร้าง GitHub สาธารณะ
ปล่อย.

## เผยแพร่การเผยแพร่

จากสาขา `main` ที่สะอาดและผ่านการตรวจสอบแล้ว:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

แท็กเริ่มเวิร์กโฟลว์การเผยแพร่ มัน:

1. ติดตั้งการพึ่งพาบิลด์ที่ปักหมุดไว้
2. สร้างข้อมูลเมตาเวอร์ชัน Windows ที่ตรงกัน
3. สร้างไฟล์ปฏิบัติการ GUI และ CLI ที่มีอยู่ในตัวเอง
4. ลงชื่อปฏิบัติการเมื่อมีการกำหนดค่าการลงนามความลับ
5. สร้างตัวติดตั้ง Inno Setup ต่อผู้ใช้
6. ลงนามผู้ติดตั้งเมื่อกำหนดค่า
7. สร้างไฟล์เช็คซัมแบบพกพา ZIP และ SHA-256
8. อัปโหลดสิ่งประดิษฐ์ของเวิร์กโฟลว์
9. สร้าง GitHub Release สำหรับแท็กที่พุช

ตรวจสอบตัวติดตั้งและไฟล์เก็บถาวรแบบพกพาบนระบบ Windows ที่สะอาดก่อนประกาศการเผยแพร่
รักษาแหล่งที่มาให้สอดคล้องกับไบนารีแบบกระจายทุกตัวที่มีอยู่ภายใต้แท็ก release เดียวกัน
ยืนยันว่าปุ่ม GitHub ชี้ไปที่ URL ที่เก็บข้อมูลสาธารณะสุดท้ายก่อนที่จะแท็กรายการแรก
ปล่อย
