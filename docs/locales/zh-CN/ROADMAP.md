# MeshMill 路线图

## 平台支持

Windows是最初的封装平台。应用程序架构和网格格式是
跨平台，未来版本应添加本机 Linux 和 macOS 包。平台工作
包括打包、应用程序集成、硬件指标、文件系统行为和自动化
发布测试，同时在每个受支持的系统上保留相同的项目和 STL 工作流程。

- 添加 Linux x86-64 软件包和 CI 覆盖范围。
- 添加 macOS Apple 芯片和 x86-64 软件包、签名、公证和 CI 覆盖范围。
- 在共享接口后面添加平台本机 CPU、内存和 GPU 指标提供程序。
- 保持保存的设置、键盘映射、命令行行为和项目数据的可移植性。

该路线图记录了计划的工作。它没有描述当前版本中的功能。

## 适用范围

MeshMill 管理几何体、网格密度、点密度、优化、清理、验证和 STL
交换如此大或重的网格文件在下游编辑工作流程中仍然有用。

通用建模、雕刻、绘画、动画、渲染、场景合成、材质、
绑定和其他内容创建系统不在此路线图之内。分布式合成适用
MeshMill的网格管理操作并没有将产品扩展为通用编辑器。

## 参考几何形状

捆绑复合网格是当前算法和路线图的常见开发工具
工作。其故意冗余的层和不均匀的密度支持可重复的比较
还原质量、密度分析、重叠处理、区域操作、核外处理、
以及未来的综合。路线图实施应报告针对此固定装置和小型装置的结果
专门构建的回归网格，而不是单独优化一个模型的行为。

## 多 STL 工作区和统计综合

工作区应接受多个 STL 输入作为单独的、独立可见的源对象。
MeshMill 应该对齐这些源，测量它们的几何一致性，并合成一个可用的
网格划分而不保留重复的内表面或重复的重叠几何体。

计划的行为：

- 在一个工作区中添加、删除、隐藏、隔离、重新排序和检查多个 STL 源；
- 保留源标识、单位、变换、边界、分辨率和操作历史记录；
- 提供自动配准、手动对齐控制和可测量的贴合质量；
- 在比较之前将源划分为空间区域，以便大的输入保持有限；
- 分析占用率、最近表面距离、正态一致性、局部密度、方差和
  重叠区域的观察计数；
- 对匹配表面、冲突表面、扫描噪声、间隙和独特几何形状进行分类；
- 将统计上一致的表面合并为具有记录的代表性表面
  信心而不是堆叠重复的三角形；
- 删除不提供外部形状细节的封闭、重合和共享几何图形；
- 保留不重叠的源几何图形并暴露模糊区域以供视觉检查；
- 当一次扫描更清晰或更详细时，允许按源和按区域加权；
- 综合后验证水密性、边界、法线、尺寸和拓扑；
- 记录源出处和合成参数，以便组合网格可重现；
- 预览之前预期的三角形数量、边界、重叠去除和置信度分布
  提交合成结果。

此工作流程应使用为大型项目规划的相同的外核空间索引和工作单元模型。
网格。统计比较和重叠合并也应该可以分布在当地
或远程 MeshMill 节点。

## 分布式合成

MeshMill 集群应协调跨多个并行操作的多个节点
工作站。节点可以检查、选择、减少、验证、修复或组合指定的区域或
工作单位。在经过审查和合并之前，贡献将保持独立版本
进入共享对象版本。

系统应支持：

- 来自多个操作员和自动化节点的并发贡献；
- 确定性工作单元输入、参数、依赖性和输出；
- 基于CPU、GPU、内存、算法和当前负载的能力感知调度；
- 网格、区域、验证过程和综合阶段的依赖感知分区；
- 具有暂停、恢复、取消、重试、重新分配和故障恢复功能的持久队列；
- 节点之间的内容寻址工件和完整性检查；
- 从一组记录的已接受贡献版本中进行可重复的合成；
- 离线或间歇性连接的工作站可以稍后同步；
- 本地优先操作，对参与节点和共享项目数据进行明确控制。

## 版本化协作

每个贡献都应记录其父对象版本、所选区域或工作单位、操作、
参数、节点身份、时间戳、依赖项、验证结果和输出校验和。

计划的协作行为：

- 项目包含对象、分支、检查点、贡献和综合版本；
- 贡献者可以在同一父版本中工作，而无需相互覆盖；
- 不重叠的贡献可以在验证后自动合并；
- 重叠的几何图形或不兼容的依赖关系会产生明显的冲突；
- 冲突提供视觉比较、区域级选择、变基、重新运行和手动解决；
- 审查状态包括待决、接受、拒绝、取代、冲突和合并；
- 最终的综合清单标识了每个合并的贡献和依赖项。

## 协调用户界面

桌面应用程序应该管理分布式工作，而不需要单独的命令行
或服务器管理工作流程。规划景观包括：

- **项目：**对象、分支、版本、贡献者和综合状态。
- **集群：**连接的工作站和节点、功能、运行状况、负载和当前分配。
- **队列：**待处理、活动、暂停、阻止、失败和已完成的工作单元。
- **贡献：** 作者、节点、父版本、受影响区域、参数、检查和审核状态。
- **比较：**同步 3D 视图、几何差异、指标和边界检查。
- **冲突：**重叠区域、依赖冲突、解决方案选择和验证结果。
- **综合：**依赖关系图、聚合进度、选定的贡献版本和最终输出。
- **历史记录：**分支图、检查点、合并、合成版本和再现性清单。

视口应显示所有权、分配的区域、已完成的工作、待处理的更改、冲突、
和版本差异而不改变底层网格。

## 协调和运输

第一个设计阶段应在选择传输之前定义协议边界。协议
应将协调元数据与大型网格工件分开，支持可恢复传输，并且
无需外部帐户或托管服务即可在本地网络上保持可用。

所需的协调概念：

- 协调员选举或明确选定的协调员；
- 节点发现和手动节点注册；
- 经过身份验证的会话和项目范围的授权；
- 工作所有权的租赁和心跳；
- 幂等工作提交和结果接受；
- 不同MeshMill版本之间的版本协商；
- 进度、日志、验证、失败和重试的结构化事件；
- 协调器、工作站、网络或节点中断后的恢复。

## 交付阶段

### 阶段0：核外大网格处理

索引、流、缓存、工作单元和安全契约记录在
[`docs/OUT_OF_CORE.md`](docs/OUT_OF_CORE.md)。

- 在分配完整网格之前估计三角形数量和工作内存。
- 打开超大二进制 STL 文件作为有界、均匀采样的导航概述。
- 将全分辨率几何体划分为具有确定性重叠边界的空间立方体。
- 在 CPU 和内存限制内同时读取、分析和优化独立多维数据集。
- 流式传输从粗到细的视口级别，而不需要内存中的完整网格。
- 直接在视口中绘制立方体状态：排队、读取、处理、完成和失败。
- 通过填充每个立方体来显示每个立方体的进度并保留高级整体对象视图。
- 通过边界验证、重复删除和可重现设置来组装经过处理的立方体。
- 在后续阶段将本地立方体调度程序扩展到分布式综合工作单元。

### 第一阶段：版本化本地基础

- 定义对象、操作、贡献、分支和清单格式。
- 添加具有每个源可见性、转换、元数据和来源的多 STL 工作区。
- 添加配准质量指标和空间重叠分类。
- 合成统计上一致的曲面，同时删除重复和封闭的几何图形。
- 添加针对某一来源特有的冲突、差距、置信度和几何图形的视觉审查。
- 跨应用程序会话保留本地历史记录。
- 添加视觉网格和区域比较。
- 使操作具有确定性且可独立重现。

### 第2阶段：协调本地节点

- 在一台工作站上运行工作节点。
- 添加排队、能力报告、工作分配和取消。
- 在 MeshMill UI 中显示节点和工作单元状态。
- 在本地验证分区和结果组装。

### 第三阶段：多工作站综合

- 添加经过身份验证的 LAN 发现和注册。
- 通过简历支持传输内容寻址的工作投入和结果。
- 协调多个工作站的并发工作。
- 在节点或网络故障后恢复分配。

### 第四阶段：协作版本控制

- 添加贡献者、分支、审核状态和权限。
- 合并不重叠的贡献。
- 检测并解决重叠或依赖性冲突。
- 将选定的贡献合成为可重现的对象版本。

### 第五阶段：生产强化

- 添加协议兼容性测试和混合版本处理。
- 添加审计、完整性、损坏、中断和恢复测试。
- 对调度、分区、传输、合并和综合性能进行基准测试。
- 文档部署、备份、迁移和事件恢复。
