# 贡献

欢迎通过问题和拉取请求做出贡献。

## 项目范围

MeshMill 使超大、密集或困难的网格文件易于管理，以便下游编辑和
生产工作流程。贡献应改进几何检查、网格和点密度
管理、优化、选择、裁剪、清理、验证、STL 交换、性能、
或这些行动的协调。

该项目不包括通用建模、雕刻、绘画、动画、渲染、
场景合成、材质、装备或其他内容创建系统。提案介绍
这些功能超出了项目范围。

新功能应该让应用程序保持专注，保留直接的工作流程
将几何图形转换为可管理的网格，并避免将支持控件转变为一般编辑
环境。

## 本地化

英文UI源文本存储在`locales/en-US.json`中。区域设置元数据存储在
`locales/manifest.json`。翻译后的 UI 目录使用相同的稳定密钥和文件名
`<locale>.json`。翻译后的文档使用匹配的根文件名
`docs/locales/<locale>/`。

翻译最初是通过外部机器翻译服务生成的，并接收
自动结构验证。该过程不能保证自然、技术精确或
上下文正确的语言。鼓励母语人士审阅并更正翻译后的用户界面
文本和文档。翻译更正应保留目录键、占位符、
命令、链接、测量、产品名称和 Markdown 结构。

更改标签、工具提示、对话框或其他用户可见文本后，运行：

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
```

一起查看源更改和重新生成的密钥。

## 几何和算法的变化

在更改优化、密度分析、选择、裁剪时使用捆绑的样本几何形状，
大文件处理或视口比较行为。它故意包含冗余层
和不均匀的密度，因此一个有用的结果应该提高可管理性而不隐藏失真，
丢弃有意义的边界，或者默默地删除另一个算法保留的几何图形。

记录输入、算法、设置、三角形计数、尺寸、尺寸漂移、经过的时间、
以及相关截图进行比较。测试较小的普通 Git 固定装置，并且当
更改涉及大型或分层几何形状，原始 Git LFS 夹具。不要调整算法
仅针对此固定装置。为特定的不变量或回归添加小型综合案例
已测试。

比较清单请参见[算法测试和贡献](docs/ALGORITHM_TESTING.md)。

## 开发设置

1. 在 Windows 上安装 64 位 Python 3.12。
2. 创建并激活虚拟环境。
3. 安装 `requirements-dev.txt`。
4. 运行 `python meshmill.py` 用于 GUI 或 `python meshmill.py --help` 用于 CLI 使用。
5. 在提交更改之前运行 `python -m py_compile meshmill.py`。

保留私有网格、生成的可执行文件、包含私有信息的屏幕截图以及本地
从提交中构建目录。可再分配测试几何体属于 `samples/` 及其
记录来源、许可证、尺寸和生成方法。新的源文件应该使用
SPDX 标识符 `GPL-3.0-or-later`。

将每个文档屏幕截图裁剪为 MeshMill 应用程序内容。不包括
任务栏、不相关的窗口镶边、通知、帐户详细信息、私有路径或背景
桌面内容。
