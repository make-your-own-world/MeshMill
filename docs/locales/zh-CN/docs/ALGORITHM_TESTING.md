# 算法测试与贡献

MeshMill 算法应该使困难的几何图形易于管理，同时保持其效果可见，
在应用结果之前可测量且可逆。

## 参考夹具

使用复合样本几何体的两个捆绑版本：

- `samples/sample-scan.stl` 是较小的普通 Git 夹具，用于日常开发、自动化
  检查并学习控制。
- `samples/original-scan.stl` 是完整的 Git LFS 夹具，适用于大文件行为、冗余层、
  密度不均匀、重叠和性能工作。

冗余和密集区域是有意的测试特征。测试可能会针对他们，但是
不应假设每个重叠表面都是一次性的。添加紧凑的合成网格
变化需要已知的边界、曲率、拓扑、密度或重叠不变量。

## 比较清单

对于算法或参数更改，记录：

- MeshMill 版本或提交；
- 输入夹具和校验和；
- 算法、质量预设、目标和高级设置；
- 原始和生成的三角形和顶点数；
- 减少百分比、尺寸和尺寸漂移；
- 当性能相关时，经过的时间和峰值内存；
- 相同保存视图和显示模式的屏幕截图；
- 可见的边界、孔洞、自相交、重叠或扭曲变化；
- 结果是否来自整个网格或仅选择操作。

与同一目标的当前行为进行比较，而不仅仅是与另一个带有
不同的输出计数。检查适用的阴影、密度、线框和顶点显示。

## 验收指导

优化更改应避免意外的尺寸变化、明显的表面反转、
处理区域之间的裂缝、有意义的边界的丢失以及大量的质量回归
类似的输出计数。以密度为导向的变化应该表明去除的浓度确实
不携带有用的曲率或拓扑。

性能结果应确定处理器、内存容量、图形硬件、操作
系统、输入大小以及数据是否已缓存。结构验证和屏幕截图
支持审查，但不能取代熟悉源几何的贡献者的检查。

## 回归测试

更喜欢具有明确容差的确定性测试。保持新的固定装置对于正常的 Git 来说足够小，
记录其来源和许可，并在不需要真实源数据时使用合成几何。
当操作可以修改几何时，测试应涵盖取消和状态恢复。
