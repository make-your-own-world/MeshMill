# 核外网状架构

MeshMill当前的大文件保护措施在分配完整的文件之前估计工作内存
网格。超出配置预算的文件可以作为有界导航概述打开。安
概述是采样的几何体，明显地被识别为这样的，并且不能被编辑或导出为
尽管它是完整的来源。

真正依赖于缩放的细节需要持久的空间索引。下面的设计定义了
下一个实施阶段。

## 索引格式

每个源网格都会收到一个版本化的 `.meshmill-index` 目录，其中包含：

- `manifest.json`，包含源大小、修改时间、采样内容哈希值、边界、
  三角形计数、索引版本、坐标精度和级别描述；
- 由八叉树级别和莫顿代码寻址的空间图块；
- 每个占用的父图块的粗略显示网格；
- 叶子图块中的全分辨率三角形记录；和
- 区域行动和集结期间使用的边界所有权和重叠元数据。

索引创建在有界块中按顺序读取源。它写入临时图块运行并
在每个所需的文件通过验证后自动发布清单。中断或
从其清单中检测到过时的索引，并且可以在不打开完整索引的情况下恢复或重建
内存中的网格。

## 视口流式传输

视口使用相机视锥体和屏幕空间误差来选择图块。粗母瓷砖是
首先显示。当相机靠近时，可见的子图块会替换它们，而在屏幕外和
低影响瓷砖仍然粗糙。 RAM 和 VRAM 具有独立的预算和最近最少使用的
缓存。释放细节永远不会释放粗略的整体对象表示。

调度程序记录这些图块状态：排队、读取、处理、上传、驻留、失败、
并取消。视口可以按状态为立方体着色，并按其比例填充每个立方体。
进步。取消会删除部分结果，并使最后的完整表示保持活动状态。

## 加工及产能

本地工作单元是一个图块加上其操作所需的确定性重叠。并发性
受当前可用的 RAM、配置的内存百分比、逻辑处理器数量和
测量的工作单元尺寸。 GPU 上传和显示有单独的 VRAM 预算。报告平行
容量是在测量代表性瓷砖之前的估计值。

操作为每个边界元素保留一个所有者。装配体验证共享边界，
删除重复项，检查计数和边界，并记录所使用的确切参数。相同的工作
单元和结果格式稍后可以跨分布式综合节点进行调度。

## 安全规则

- 全局样本被标记为概述，而不是全分辨率视口细节。
- 概览无法覆盖或导出为完整的源网格。
- 超出当前预算的满载请求需要明确的选择。
- 索引生成、图块处理和组装仍然可以取消并保留以前的
  完整状态。
- 容量值是估计值，并确定它们是描述当前发动机还是计划的发动机
  并行瓦片执行。
