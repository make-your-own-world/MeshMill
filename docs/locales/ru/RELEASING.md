# Выпуск MeshMill

Конвейер стабильных выпусков создает артефакты Windows на средах выполнения Windows, размещенных на GitHub. Отдельный
ручной рабочий процесс создает неподписанные предварительные версии процессоров Intel/Apple для Linux x86-64 и macOS на встроенной основе.
Бегуны, размещенные на GitHub. Конечные пользователи не устанавливают Python, Node.js или зависимости.

Перед сборкой обновите и проверьте исходные каталоги локализации:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## До первого публичного релиза

1. Завершите и утвердите запланированные переводы приложений и документации.
2. Ознакомьтесь с лицензией GPL и уведомлениями третьих сторон.
3. Тестовая установка, запуск, загрузка STL, оптимизация, экспорт и удаление на чистом компьютере.
   Учетная запись Windows или виртуальная машина.
4. Запустите CI против `samples/sample-scan.stl`. Проверьте каждый скриншот документации и обрежьте его.
   панель задач, хром окна, не являющийся частью MeshMill, уведомления, личные пути, учетная запись
   подробности и несвязанный контент рабочего стола перед публикацией.
5. Настройте локального автора Git в репозитории, указав неответный адрес учетной записи GitHub перед
   первый коммит. Подтвердите это с помощью `git config --local --get user.email`.
6. Настройте дополнительные секреты подписи Authenticode:
   - `WINDOWS_CERTIFICATE_BASE64`: сертификат PFX в кодировке Base64.
   - `WINDOWS_CERTIFICATE_PASSWORD`: пароль PFX.

Без сертификата подписи сгенерированные файлы по-прежнему работают, но Windows SmartScreen может отображать
предупреждение неизвестного издателя. Не называйте неподписанные сборки подписанными или доверенными.

## Оригинальный скан и Git LFS

`samples/original-scan.stl` отслеживается через Git LFS, поскольку он превышает обычные 100 МБ для GitHub.
лимит файла. Перед первым коммитом проверьте:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

Фильтр должен быть `lfs`, а идентификатор объекта указателя должен соответствовать `samples/SHA256SUMS.txt`. Релиз
рабочий процесс проверяет содержимое LFS и публикует исходный STL как отдельный ресурс выпуска. CI использует
меньший образец обычного Git и не загружает объект LFS.

## Протестируйте выпускную сборку без публикации

Откройте **Действия**, выберите **Освободить**, выберите **Запустить рабочий процесс** и введите числовую версию, например
`0.1.0`. При запуске вручную загружаются артефакты рабочего процесса для тестирования, но не создается общедоступный файл GitHub.
Выпуск.

## Опубликовать релиз

Из чистой, проверенной ветки `main`:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

Тег запускает рабочий процесс выпуска. Это:

1. устанавливает закрепленные зависимости сборки;
2. генерирует соответствующие метаданные версии Windows;
3. создает автономные исполняемые файлы графического пользовательского интерфейса и командной строки;
4. подписывает исполняемые файлы при настройке секретов подписи;
5. создает установщик Inno Setup для каждого пользователя;
6. подписывает установщик при настройке;
7. создает переносимый файл контрольной суммы ZIP и SHA-256;
8. загружает артефакты рабочего процесса;
9. создает выпуск GitHub для отправленного тега.

Прежде чем объявлять о выпуске, проверьте установщик и переносимый архив на чистой системе Windows.
Сохраняйте исходный код, соответствующий каждому распространяемому двоичному файлу, доступному под одним и тем же тегом выпуска.
Прежде чем пометить первый тег, убедитесь, что кнопка GitHub указывает на окончательный URL-адрес общедоступного репозитория.
выпуск.

## Создание превью-версий Linux и macOS

Откройте **Действия**, выберите **Предварительные сборки платформы** и выберите **Запустить рабочий процесс**. Введите предварительный просмотр
версия, например `0.2.0-preview.1`.

Оставьте параметр **Опубликовать общедоступную предварительную версию GitHub** отключенным при первом запуске. Рабочий процесс строит и тестирует:

- Linux x86-64 на Ubuntu 22.04;
- macOS x86-64 на платформе Intel;
- macOS Arm64 на кремниевом шасси Apple.

Загрузите артефакты рабочего процесса и проверьте их контрольные суммы и журналы. Запустите рабочий процесс еще раз с помощью
публикация включается только после прохождения каждого задания сборки. Опубликованные превью-версии macOS имеют специальную подпись,
не нотариально заверенный Apple. Опишите их как предварительные сборки и дайте ссылку на тестировщиков.
`docs/PLATFORM_TESTING.md` и форма выпуска **Предварительного теста платформы**.
