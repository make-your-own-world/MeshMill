# Тестирование алгоритмов и вклад

Алгоритмы MeshMill должны сделать сложную геометрию управляемой, сохраняя при этом ее эффекты видимыми.
измеримы и обратимы до того, как будет применен результат.

## Эталонные светильники

Используйте обе объединенные версии геометрии составного образца:

- `samples/sample-scan.stl` — это меньшее по размеру стандартное приспособление Git для рутинной автоматизированной разработки.
  проверки и изучение элементов управления.
- `samples/original-scan.stl` — это полная версия Git LFS для работы с большими файлами, избыточными слоями,
  неравномерная плотность, перекрытие и производительность работы.

Избыточные и плотные области являются преднамеренными тестовыми характеристиками. Тест может быть нацелен на них, но
не следует предполагать, что каждая перекрывающаяся поверхность является одноразовой. Добавляйте компактные синтетические сетки, когда
для изменения необходима известная граница, кривизна, топология, плотность или инвариант перекрытия.

## Контрольный список сравнения

При изменении алгоритма или параметра запишите:

- Версия MeshMill или коммит;
- входная фиксация и контрольная сумма;
- алгоритм, предустановка качества, целевые и дополнительные настройки;
- количество исходных и результирующих треугольников и вершин;
- процент уменьшения, размеры и дрейф размеров;
- прошедшее время и пиковая память, когда производительность важна;
- скриншоты из тех же сохраненных видов и режимов отображения;
- видимые границы, дыры, самопересечения, перекрытия или изменения искажений;
- получен ли результат в результате операции всей сетки или операции только выбора.

Сравните с текущим поведением той же цели, а не только с другим пресетом с
разное количество выходов. Проверьте затенение, плотность, каркасное отображение и отображение вершин, где это применимо.

## Руководство по приемке

Изменение оптимизации должно избегать неожиданных изменений размеров, очевидной инверсии поверхности,
трещины между обработанными областями, потеря значимых границ и большая регрессия качества за один раз.
аналогичное количество выходов. Изменения, ориентированные на плотность, должны продемонстрировать, что удаленная концентрация
не несут полезной кривизны или топологии.

Результаты производительности должны идентифицировать процессор, объем памяти, графическое оборудование, операционную систему.
система, размер ввода и были ли данные уже кэшированы. Структурная проверка и снимки экрана
поддерживать проверку, но не заменять проверку участниками, знакомыми с исходной геометрией.

## Регрессионные тесты

Отдавайте предпочтение детерминированным тестам с явными допусками. Сохраняйте новые фикстуры достаточно маленькими для обычного Git.
документируйте их происхождение и лицензию и используйте синтетическую геометрию, когда реальные исходные данные не нужны.
Тесты должны охватывать отмену и восстановление состояния, когда операция может изменить геометрию.
