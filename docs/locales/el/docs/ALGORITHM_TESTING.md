# Δοκιμή αλγορίθμων και συνεισφορά

Οι αλγόριθμοι MeshMill θα πρέπει να κάνουν τη δύσκολη γεωμετρία διαχειρίσιμη, διατηρώντας τα εφέ τους ορατά,
μετρήσιμο και αναστρέψιμο πριν εφαρμοστεί ένα αποτέλεσμα.

## Εξαρτήματα αναφοράς

Χρησιμοποιήστε και τις δύο ομαδοποιημένες εκδόσεις του σύνθετου δείγματος γεωμετρίας:

- Το `samples/sample-scan.stl` είναι το μικρότερο κανονικό εξάρτημα Git για καθημερινή ανάπτυξη, αυτοματοποιημένο
  ελέγχους και εκμάθηση των ελέγχων.
- Το `samples/original-scan.stl` είναι το πλήρες εξάρτημα Git LFS για συμπεριφορά μεγάλων αρχείων, πλεονάζοντα επίπεδα,
  ανομοιόμορφη πυκνότητα, επικάλυψη και εργασία απόδοσης.

Οι περιττές και οι πυκνές περιοχές είναι σκόπιμα χαρακτηριστικά δοκιμής. Μια δοκιμή μπορεί να τους στοχεύει, αλλά
δεν πρέπει να υποθέσουμε ότι κάθε επικαλυπτόμενη επιφάνεια είναι μίας χρήσης. Προσθέστε συμπαγή συνθετικά πλέγματα όταν α
Η αλλαγή χρειάζεται ένα γνωστό όριο, καμπυλότητα, τοπολογία, πυκνότητα ή αμετάβλητη επικάλυψη.

## Λίστα ελέγχου σύγκρισης

Για αλλαγή αλγορίθμου ή παραμέτρου, καταγράψτε:

- Έκδοση ή δέσμευση MeshMill.
- εξάρτημα εισόδου και άθροισμα ελέγχου.
- αλγόριθμος, προκαθορισμένη ποιότητα, στόχος και προηγμένες ρυθμίσεις.
- αρχικές και προκύπτουσες μετρήσεις τριγώνων και κορυφών.
- ποσοστό μείωσης, διαστάσεις και μετατόπιση διαστάσεων.
- χρόνος που έχει παρέλθει και μέγιστη μνήμη όταν η απόδοση είναι σχετική.
- στιγμιότυπα οθόνης από τις ίδιες αποθηκευμένες προβολές και λειτουργίες εμφάνισης.
- αλλαγές ορατών ορίων, οπών, αυτοτομής, επικάλυψης ή παραμόρφωσης.
- είτε το αποτέλεσμα προήλθε από λειτουργία πλήρους πλέγματος ή μόνο επιλογής.

Συγκρίνετε με την τρέχουσα συμπεριφορά στον ίδιο στόχο, όχι μόνο με μια άλλη προεπιλογή με α
διαφορετικό πλήθος εξόδου. Επιθεωρήστε τις σκιασμένες οθόνες, την πυκνότητα, το πλαίσιο και τις κορυφές όπου υπάρχουν.

## Οδηγίες αποδοχής

Μια αλλαγή βελτιστοποίησης θα πρέπει να αποφεύγει απροσδόκητες αλλαγές διαστάσεων, εμφανή αναστροφή επιφάνειας,
ρωγμές μεταξύ επεξεργασμένων περιοχών, απώλεια σημαντικών ορίων και μεγάλες παλινδρομήσεις ποιότητας σε α
παρόμοιο αριθμό εξόδου. Οι αλλαγές προσανατολισμένες στην πυκνότητα θα πρέπει να αποδεικνύουν ότι η αφαιρεθείσα συγκέντρωση έγινε
δεν φέρουν χρήσιμη καμπυλότητα ή τοπολογία.

Τα αποτελέσματα απόδοσης πρέπει να προσδιορίζουν τον επεξεργαστή, τη χωρητικότητα μνήμης, το υλικό γραφικών, τη λειτουργία
σύστημα, μέγεθος εισόδου και εάν τα δεδομένα ήταν ήδη αποθηκευμένα στην κρυφή μνήμη. Δομική επικύρωση και στιγμιότυπα οθόνης
υποστηρίζει την αναθεώρηση, αλλά μην αντικαθιστά την επιθεώρηση από συνεργάτες που είναι εξοικειωμένοι με τη γεωμετρία της πηγής.

## Δοκιμές παλινδρόμησης

Προτιμήστε ντετερμινιστικές δοκιμές με ρητές ανοχές. Διατηρήστε τα νέα φωτιστικά αρκετά μικρά για κανονικό Git,
τεκμηριώστε την προέλευση και την άδεια χρήσης τους και χρησιμοποιήστε συνθετική γεωμετρία όταν τα πραγματικά δεδομένα πηγής δεν είναι απαραίτητα.
Οι δοκιμές θα πρέπει να καλύπτουν την ακύρωση και την αποκατάσταση κατάστασης όταν μια λειτουργία μπορεί να τροποποιήσει τη γεωμετρία.
