# Κυκλοφορεί το MeshMill

Ο αγωγός σταθερής απελευθέρωσης δημιουργεί τεχνουργήματα των Windows σε προγράμματα εκτέλεσης Windows που φιλοξενούνται στο GitHub. Ένα ξεχωριστό
μη αυτόματη ροή εργασιών δημιουργεί ανυπόγραφες προεπισκοπήσεις πυριτίου Linux x86-64 και macOS Intel/Apple σε εγγενή
Δρομείς που φιλοξενούνται από το GitHub. Οι τελικοί χρήστες δεν εγκαθιστούν Python, Node.js ή εξαρτήσεις.

Πριν από τη δημιουργία, ανανεώστε και επικυρώστε τους καταλόγους πηγών εντοπισμού:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## Πριν την πρώτη δημόσια κυκλοφορία

1. Ολοκληρώστε και επικυρώστε τις προγραμματισμένες μεταφράσεις εφαρμογής και τεκμηρίωσης.
2. Ελέγξτε την GPL και τις ειδοποιήσεις τρίτων.
3. Δοκιμή εγκατάστασης, εκκίνησης, φόρτωση STL, βελτιστοποίηση, εξαγωγή και απεγκατάσταση σε καθαρό
   Λογαριασμός Windows ή εικονική μηχανή.
4. Εκτελέστε το CI έναντι του `samples/sample-scan.stl`. Επιθεωρήστε κάθε στιγμιότυπο οθόνης τεκμηρίωσης και αποκόψτε το
   τη γραμμή εργασιών, το παράθυρο chrome που δεν αποτελεί μέρος του MeshMill, τις ειδοποιήσεις, τις ιδιωτικές διαδρομές, τον λογαριασμό
   λεπτομέρειες και άσχετο περιεχόμενο επιφάνειας εργασίας πριν από τη δημοσίευση.
5. Διαμορφώστε τον συντάκτη του αποθετηρίου-τοπικού Git με τη διεύθυνση μη απάντησης GitHub του λογαριασμού πριν από το
   πρώτη δέσμευση. Επιβεβαιώστε το με `git config --local --get user.email`.
6. Διαμόρφωση προαιρετικών μυστικών υπογραφής Authenticode:
   - `WINDOWS_CERTIFICATE_BASE64`: Πιστοποιητικό PFX με κωδικοποίηση Base64.
   - `WINDOWS_CERTIFICATE_PASSWORD`: Κωδικός πρόσβασης PFX.

Χωρίς πιστοποιητικό υπογραφής, τα αρχεία που δημιουργούνται εξακολουθούν να λειτουργούν, αλλά το Windows SmartScreen μπορεί να εμφανίσει
μια προειδοποίηση μη αναγνωρισμένου εκδότη. Μην περιγράφετε τις ανυπόγραφες εκδόσεις ως υπογεγραμμένες ή αξιόπιστες.

## Σάρωση πρωτότυπου και Git LFS

Το `samples/original-scan.stl` παρακολουθείται μέσω του Git LFS επειδή υπερβαίνει τα κανονικά 100 MiB του GitHub
όριο αρχείου. Πριν από την πρώτη δέσμευση, επαληθεύστε:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

Το φίλτρο πρέπει να είναι `lfs` και το αναγνωριστικό αντικειμένου δείκτη πρέπει να ταιριάζει με το `samples/SHA256SUMS.txt`. Η απελευθέρωση
Η ροή εργασιών ελέγχει το περιεχόμενο LFS και δημοσιεύει το αρχικό STL ως ξεχωριστό στοιχείο έκδοσης. CI χρήσεις
το μικρότερο δείγμα normal-Git και δεν πραγματοποιεί λήψη του αντικειμένου LFS.

## Δοκιμάστε μια έκδοση έκδοσης χωρίς δημοσίευση

Ανοίξτε τις **Ενέργειες**, επιλέξτε **Απελευθέρωση**, επιλέξτε **Εκτέλεση ροής εργασιών** και εισαγάγετε μια αριθμητική έκδοση όπως π.χ.
`0.1.0`. Μια μη αυτόματη εκτέλεση μεταφορτώνει τεχνουργήματα ροής εργασίας για δοκιμή, αλλά δεν δημιουργεί δημόσιο GitHub
Απελευθέρωση.

## Δημοσιεύστε μια έκδοση

Από ένα καθαρό, αξιολογημένο υποκατάστημα `main`:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

Η ετικέτα ξεκινά τη ροή εργασίας απελευθέρωσης. Αυτό:

1. εγκαθιστά τις καρφιτσωμένες εξαρτήσεις κατασκευής.
2. δημιουργεί τα αντίστοιχα μεταδεδομένα έκδοσης Windows.
3. δημιουργεί τα αυτόνομα εκτελέσιμα GUI και CLI.
4. υπογράφει τα εκτελέσιμα κατά τη διαμόρφωση των μυστικών υπογραφής.
5. δημιουργεί το πρόγραμμα εγκατάστασης Inno Setup ανά χρήστη.
6. υπογράφει το πρόγραμμα εγκατάστασης όταν ρυθμιστεί.
7. δημιουργεί το φορητό αρχείο ZIP και SHA-256 checksum.
8. μεταφορτώνει τεχνουργήματα ροής εργασίας.
9. δημιουργεί την έκδοση GitHub για την πιεσμένη ετικέτα.

Επαληθεύστε το πρόγραμμα εγκατάστασης και το φορητό αρχείο σε ένα καθαρό σύστημα Windows πριν ανακοινώσετε την κυκλοφορία.
Διατηρήστε την πηγή που αντιστοιχεί σε κάθε διανεμημένο δυαδικό αρχείο που είναι διαθέσιμο κάτω από την ίδια ετικέτα έκδοσης.
Επιβεβαιώστε ότι το κουμπί GitHub οδηγεί στην τελική διεύθυνση URL δημόσιου χώρου αποθήκευσης πριν προσθέσετε ετικέτα στο πρώτο
απελευθέρωση.

## Δημιουργήστε προεπισκοπήσεις Linux και macOS

Ανοίξτε τις **Ενέργειες**, επιλέξτε **Εκδόσεις προεπισκόπησης πλατφόρμας** και επιλέξτε **Εκτέλεση ροής εργασίας**. Εισαγάγετε μια προεπισκόπηση
έκδοση όπως "0.2.0-preview.1".

Αφήστε εκτός λειτουργίας **Δημοσίευση δημόσιας προέκδοσης του GitHub** για την πρώτη εκτέλεση. Η ροή εργασίας δημιουργεί και δοκιμάζει:

- Linux x86-64 στο Ubuntu 22.04.
- macOS x86-64 σε πρόγραμμα εκτέλεσης Intel.
- macOS arm64 σε δρομέα πυριτίου της Apple.

Κατεβάστε τα τεχνουργήματα ροής εργασίας και επιθεωρήστε τα αθροίσματα ελέγχου και τα αρχεία καταγραφής τους. Εκτελέστε ξανά τη ροή εργασίας με
Η δημοσίευση ενεργοποιείται μόνο αφού περάσει κάθε εργασία κατασκευής. Οι δημοσιευμένες προεπισκοπήσεις macOS έχουν υπογραφεί ad-hoc,
μη επικυρωμένο από την Apple. Περιγράψτε τα ως εκδόσεις προεπισκόπησης και συνδέστε τους ελεγκτές με
«docs/PLATFORM_TESTING.md» και τη φόρμα ζητήματος **Δοκιμή προεπισκόπησης πλατφόρμας**.
