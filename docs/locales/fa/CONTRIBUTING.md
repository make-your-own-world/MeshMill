# کمک کردن

مشارکت از طریق مسائل و درخواست های کششی استقبال می شود.

## محدوده پروژه

MeshMill فایل های مش بزرگ، متراکم یا دشوار را برای ویرایش پایین دست قابل مدیریت می کند و
گردش کار تولید مشارکت ها باید بازرسی هندسه، مش و تراکم نقطه را بهبود بخشد
مدیریت، بهینه سازی، انتخاب، برش، پاکسازی، اعتبارسنجی، تبادل STL، عملکرد،
یا هماهنگی آن عملیات.

این پروژه شامل مدل سازی همه منظوره، مجسمه سازی، نقاشی، انیمیشن، رندر،
ترکیب صحنه، مواد، تقلب، یا سایر سیستم های تولید محتوا. پیشنهادهایی که معرفی می کنند
این ویژگی ها خارج از محدوده پروژه هستند.

ویژگی‌های جدید باید برنامه را متمرکز نگه دارند، جریان‌های کاری مستقیم را که منبع تبدیل می‌شوند حفظ کنند
هندسه را به مش های قابل مدیریت تبدیل کنید و از تبدیل کنترل های پشتیبانی به ویرایش کلی خودداری کنید
محیط زیست

## بومی سازی

متن منبع رابط کاربری انگلیسی در `locales/en-US.json` ذخیره می شود. ابرداده محلی در ذخیره می شود
`locales/manifest.json`. کاتالوگ های UI ترجمه شده از کلیدهای پایدار و نام فایل استفاده می کنند
`<locale>.json`. اسناد ترجمه شده از نام فایل ریشه منطبق در زیر استفاده می کند
`docs/locales/<locale>/`.

ترجمه ها در ابتدا با خدمات ترجمه ماشینی خارجی تولید و دریافت می شوند
اعتبار سنجی ساختاری خودکار این فرآیند نمی تواند طبیعی، از نظر فنی دقیق، یا را تضمین کند
زبان درست از نظر زمینه سخنرانان بومی تشویق می شوند که رابط کاربری ترجمه شده را بررسی و تصحیح کنند
متن و مستندات اصلاحات ترجمه باید کلیدهای کاتالوگ، متغیرهایی،
دستورات، پیوندها، اندازه‌گیری‌ها، نام محصولات و ساختار Markdown.

پس از تغییر برچسب‌ها، نکات ابزار، گفتگوها یا سایر متن‌های قابل مشاهده توسط کاربر، اجرا کنید:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
```

تغییرات منبع و کلیدهای بازسازی شده را با هم مرور کنید.

## هندسه و الگوریتم تغییر می کند

هنگام تغییر بهینه سازی، تجزیه و تحلیل چگالی، انتخاب، برش، از هندسه نمونه همراه استفاده کنید.
مدیریت فایل های بزرگ یا رفتار مقایسه درگاه دید. عمدا حاوی لایه های اضافی است
و چگالی ناهموار، بنابراین یک نتیجه مفید باید مدیریت پذیری را بدون پنهان کردن اعوجاج بهبود بخشد،
دور انداختن مرزهای معنی دار، یا حذف بی سر و صدا هندسه ای که الگوریتم دیگری حفظ می کند.

ثبت ورودی، الگوریتم، تنظیمات، شمارش مثلث، ابعاد، تغییر ابعاد، زمان سپری شده،
و اسکرین شات های مربوطه برای مقایسه هم فیکسچر معمولی Git کوچکتر را تست کنید و چه زمانی که
تغییرات مربوط به هندسه بزرگ یا لایه‌ای، فیکسچر اصلی Git LFS است. یک الگوریتم را تنظیم نکنید
به این وسیله به تنهایی موارد مصنوعی کوچک را برای موجود ثابت یا رگرسیون خاص اضافه کنید
تست شده

برای چک لیست مقایسه به [آزمایش الگوریتم و مشارکت] (docs/ALGORITHM_TESTING.md) مراجعه کنید.

## راه اندازی توسعه

1. Python 3.12 64 بیتی را روی Windows نصب کنید.
2. یک محیط مجازی ایجاد و فعال کنید.
3. `requirements-dev.txt` را نصب کنید.
4. `python meshmill.py` را برای رابط کاربری گرافیکی یا `python meshmill.py --help` را برای استفاده از CLI اجرا کنید.
5. قبل از ارسال تغییر، `python -m py_compile meshmill.py` را اجرا کنید.

مش های خصوصی، فایل های اجرایی تولید شده، اسکرین شات های حاوی اطلاعات خصوصی و محلی را نگه دارید
ساخت دایرکتوری ها از commit ها هندسه آزمایشی قابل توزیع مجدد با آن به `samples/` تعلق دارد
منبع، مجوز، ابعاد و روش تولید مستند شده است. فایل های منبع جدید باید از
شناسه SPDX `GPL-3.0-or-later`.

هر اسکرین شات مستندات را به محتوای برنامه MeshMill برش دهید. را شامل نشود
نوار وظیفه، کروم پنجره نامرتبط، اعلان‌ها، جزئیات حساب، مسیرهای خصوصی یا پس‌زمینه
محتوای دسکتاپ
