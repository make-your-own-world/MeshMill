# انتشار MeshMill

خط لوله انتشار پایدار، مصنوعات ویندوز را بر روی رانرهای ویندوز میزبان GitHub ایجاد می کند. یک جدا (Windows) (Windows)
گردش کار دستی پیش‌نمایش‌های سیلیکون لینوکس x86-64 و macOS اینتل/اپل بدون امضا را روی بومی می‌سازد. (Linux)
دوندگان میزبان GitHub. کاربران نهایی پایتون، Node.js یا وابستگی‌ها را نصب نمی‌کنند. (Python)

قبل از ساخت، کاتالوگ های منبع بومی سازی را بازخوانی و اعتبارسنجی کنید:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## قبل از اولین انتشار عمومی

1. برنامه برنامه ریزی شده و ترجمه اسناد را تکمیل و تأیید کنید.
2. GPL و اعلامیه های شخص ثالث را مرور کنید.
3. تست نصب، راه‌اندازی، بارگیری STL، بهینه‌سازی، صادرات و حذف نصب در یک دستگاه تمیز
   حساب یا ماشین مجازی Windows.
4. CI را در مقابل `samples/sample-scan.stl` اجرا کنید. هر اسکرین شات مستند را بررسی کنید و بیرون بیاورید
   نوار وظیفه، پنجره کروم که بخشی از MeshMill نیست، اعلان ها، مسیرهای خصوصی، حساب کاربری
   جزئیات و محتوای دسکتاپ غیر مرتبط قبل از انتشار.
5. تنظیم کننده مخزن محلی Git با آدرس GitHub بدون پاسخ حساب قبل از
   اول ارتکاب آن را با `git config --local --get user.email` تأیید کنید.
6. پیکربندی اسرار امضای Authenticode اختیاری:
   - `WINDOWS_CERTIFICATE_BASE64`: گواهینامه PFX با کد Base64.
   - `WINDOWS_CERTIFICATE_PASSWORD`: رمز عبور PFX.

بدون گواهی امضا، فایل‌های تولید شده همچنان کار می‌کنند، اما Windows SmartScreen ممکن است نمایش داده شود
هشدار ناشر ناشناس ساخت‌های بدون امضا را به‌عنوان امضاشده یا قابل اعتماد توصیف نکنید.

## اسکن اصلی و Git LFS

`samples/original-scan.stl` از طریق Git LFS ردیابی می شود زیرا از 100 مگابایت معمولی GitHub فراتر می رود.
محدودیت فایل قبل از اولین commit، بررسی کنید:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

فیلتر باید `lfs` باشد و شناسه شی اشاره گر باید با `samples/SHA256SUMS.txt` مطابقت داشته باشد. انتشار
گردش کار محتوای LFS را بررسی می کند و STL اصلی را به عنوان دارایی انتشار جداگانه منتشر می کند. CI استفاده می کند
نمونه کوچکتر نرمال Git است و شی LFS را دانلود نمی کند.

## یک نسخه نسخه را بدون انتشار آزمایش کنید

**Actions** را باز کنید، **Release** را انتخاب کنید، **Run Workflow** را انتخاب کنید و یک نسخه عددی مانند
`0.1.0`. یک اجرای دستی مصنوعات گردش کار را برای آزمایش آپلود می کند اما یک GitHub عمومی ایجاد نمی کند
رها کنید.

## انتشار را منتشر کنید

از یک شاخه تمیز و بازبینی شده `main`:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

تگ گردش کار انتشار را شروع می کند. آن:

1. وابستگی های ساخت پین شده را نصب می کند.
2. ابرداده نسخه مشابه Windows را ایجاد می کند.
3. فایل های اجرایی GUI و CLI مستقل را می سازد.
4. هنگام پیکربندی اسرار امضا، فایل های اجرایی را امضا می کند.
5. نصب کننده Inno Setup برای هر کاربر را می سازد.
6. نصب کننده را هنگام پیکربندی امضا می کند.
7. فایل فشرده ZIP و SHA-256 قابل حمل را ایجاد می کند.
8. مصنوعات گردش کار را آپلود می کند.
9. GitHub Release را برای تگ فشار داده شده ایجاد می کند.

قبل از اعلام انتشار، نصب کننده و آرشیو قابل حمل را در یک سیستم تمیز Windows بررسی کنید.
منبع متناظر با هر باینری توزیع شده موجود را تحت همان برچسب انتشار نگه دارید.
اطمینان حاصل کنید که دکمه GitHub به نشانی اینترنتی مخزن عمومی نهایی قبل از تگ کردن اولین نشانی اینترنتی اشاره می کند.
آزاد کردن

## پیش نمایش لینوکس و macOS را بسازید (Linux)

**Actions** را باز کنید، ** ساخت‌های پیش‌نمایش پلتفرم** را انتخاب کنید و **اجرای گردش کار** را انتخاب کنید. یک پیش نمایش وارد کنید
نسخه ای مانند «0.2.0-preview.1».

**انتشار پیش انتشار عمومی GitHub** را برای اولین اجرا خاموش بگذارید. گردش کار ساخته و آزمایش می شود:

- لینوکس x86-64 در اوبونتو 22.04؛ (Linux)
- macOS x86-64 در رانر اینتل؛
- macOS arm64 در رانر سیلیکونی اپل.

مصنوعات گردش کار را دانلود کنید و چک‌سام‌ها و گزارش‌های آنها را بررسی کنید. دوباره گردش کار را با
انتشار فقط پس از اتمام هر کار ساخت فعال می شود. پیش‌نمایش‌های منتشر شده macOS دارای امضای موقت هستند،
غیر محضری اپل آنها را به‌عنوان ساخت‌های پیش‌نمایش توصیف کنید و آزمایش‌کنندگان را به آن‌ها پیوند دهید
«docs/PLATFORM_TESTING.md» و فرم مشکل **تست پیش‌نمایش پلتفرم**.
