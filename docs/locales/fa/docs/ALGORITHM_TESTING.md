# تست الگوریتم و مشارکت

الگوریتم‌های MeshMill باید هندسه دشوار را قابل مدیریت کنند و در عین حال اثرات آنها را قابل مشاهده نگه می‌دارند.
قبل از اعمال یک نتیجه قابل اندازه گیری و برگشت پذیر است.

## وسایل مرجع

از هر دو نسخه همراه هندسه نمونه ترکیبی استفاده کنید:

- `samples/sample-scan.stl` ابزار کوچکتر معمولی Git برای توسعه روتین، خودکار است.
  بررسی ها و یادگیری کنترل ها.
- `samples/original-scan.stl` فیکسچر کامل Git LFS برای رفتار فایل های بزرگ، لایه های اضافی است.
  چگالی ناهموار، همپوشانی و عملکرد کار.

مناطق زائد و متراکم از ویژگی های آزمایش عمدی هستند. یک آزمایش ممکن است آنها را هدف قرار دهد، اما
نباید فرض کرد که هر سطح روی هم یکبار مصرف است. مش های مصنوعی فشرده را زمانی که الف
تغییر به یک مرز، انحنا، توپولوژی، چگالی یا همپوشانی ثابت نیاز دارد.

## چک لیست مقایسه

برای تغییر الگوریتم یا پارامتر، ثبت کنید:

- نسخه یا commit MeshMill.
- فیکسچر ورودی و جمع کنترل;
- الگوریتم، کیفیت از پیش تعیین شده، هدف و تنظیمات پیشرفته؛
- شمارش مثلث و رأس اصلی و حاصل؛
- درصد کاهش، ابعاد و رانش ابعاد.
- زمان سپری شده و حافظه اوج زمانی که عملکرد مرتبط است.
- اسکرین شات از همان نماهای ذخیره شده و حالت های نمایش.
- مرز قابل مشاهده، سوراخ، خود تقاطع، همپوشانی، یا تغییرات اعوجاج.
- آیا نتیجه حاصل از یک عملیات مش کامل یا فقط انتخاب شده است.

با رفتار فعلی در همان هدف مقایسه کنید، نه تنها با یک از پیش تعیین شده دیگر
تعداد خروجی های مختلف در صورت لزوم، نمایشگرهای سایه دار، چگالی، قاب سیمی و رئوس را بررسی کنید.

## راهنمایی پذیرش

یک تغییر بهینه‌سازی باید از تغییرات ابعاد غیرمنتظره، وارونگی آشکار سطح جلوگیری کند.
شکاف بین مناطق پردازش شده، از دست دادن مرزهای معنی دار، و رگرسیون کیفیت بزرگ در یک
تعداد خروجی مشابه تغییرات چگالی محور باید نشان دهد که غلظت حذف شده انجام شده است
انحنا یا توپولوژی مفیدی ندارند.

نتایج عملکرد باید پردازنده، ظرفیت حافظه، سخت افزار گرافیکی، عملکرد را مشخص کند
سیستم، اندازه ورودی و اینکه آیا داده ها قبلاً در حافظه پنهان بوده اند یا خیر. اعتبار سنجی ساختاری و تصاویر
از بازبینی پشتیبانی کنید اما بازرسی توسط مشارکت کنندگان آشنا با هندسه منبع را جایگزین نکنید.

## تست های رگرسیون

تست های قطعی با تلورانس های صریح را ترجیح دهید. وسایل جدید را به اندازه کافی برای Git معمولی کوچک نگه دارید،
مبدأ و مجوز آنها را مستند کنید، و در مواقعی که داده های منبع واقعی غیر ضروری هستند، از هندسه مصنوعی استفاده کنید.
زمانی که عملیات می‌تواند هندسه را تغییر دهد، آزمایش‌ها باید لغو و بازیابی حالت را پوشش دهند.
