# MeshMill ロードマップ

## プラットフォームのサポート

Windows は、最初にパッケージ化されたプラットフォームです。アプリケーションのアーキテクチャとメッシュ形式は次のとおりです。
クロスプラットフォームであり、将来のリリースではネイティブ Linux および macOS パッケージを追加する必要があります。プラットフォームの仕事
パッケージ化、アプリケーション統合、ハードウェア メトリック、ファイル システムの動作、自動化が含まれます。
サポートされているすべてのシステムで同じプロジェクトと STL ワークフローを維持しながら、リリース テストを実行できます。

- Linux x86-64 パッケージと CI カバレッジを追加します。
- macOS Apple シリコンおよび x86-64 パッケージ、署名、公証、CI カバレッジを追加します。
- プラットフォームネイティブの CPU、メモリ、および GPU メトリクス プロバイダーを共有インターフェイスの背後に追加します。
- 保存された設定、キーボード マッピング、コマンド ラインの動作、プロジェクト データを移植可能な状態に保ちます。

このロードマップには、計画された作業が記録されます。現在のリリースの機能については説明しません。

## 範囲

MeshMill は、ジオメトリ、メッシュ密度、ポイント密度、最適化、クリーンアップ、検証、および STL を管理します
交換するため、大規模または重いメッシュ ファイルは引き続き下流の編集ワークフローで役立ちます。

汎用モデリング、スカルプト、ペイント、アニメーション、レンダリング、シーン構成、マテリアル、
リギングやその他のコンテンツ作成システムは、このロードマップの対象外です。分散合成が適用されます
MeshMill のメッシュ管理操作にのみ適用され、製品を一般的なエディタには拡張しません。

## 参照ジオメトリ

バンドルされた複合メッシュは、現在のアルゴリズムとロードマップの共通の開発備品です
仕事。意図的に冗長なレイヤーと不均一な密度により、再現可能な比較がサポートされます。
削減品質、密度分析、オーバーラップ処理、地域操作、アウトオブコア処理、
そしてこれからの合成。ロードマップの実装では、このフィクスチャと小規模なデータに対する結果を報告する必要があります。
1 つのモデルのみの動作を最適化するのではなく、専用の回帰メッシュを使用します。

## マルチ STL ワークスペースと統計的合成

ワークスペースは、複数の STL 入力を個別の独立して表示されるソース オブジェクトとして受け入れる必要があります。
MeshMill は、これらのソースを位置合わせし、幾何学的一致を測定し、使用可能な 1 つを合成する必要があります。
重複した内部サーフェスや重複したジオメトリを保持せずにメッシュを作成します。

計画された動作:

- 1 つのワークスペースで複数の STL ソースを追加、削除、非表示、分離、並べ替え、検査します。
- ソース ID、単位、変換、境界、解像度、および操作履歴を保持します。
- 手動アライメント制御による自動位置合わせと測定可能なフィット品質を提供します。
- 比較する前にソースを空間領域に分割して、大きな入力が制限されたままになるようにします。
- 占有率、最近接表面距離、正規一致、局所密度、分散、および
  重複領域にわたる観測数。
- 一致するサーフェス、競合するサーフェス、スキャン ノイズ、ギャップ、および固有のジオメトリを分類します。
- 統計的に一致する表面を、記録された代表的な表面に統合します。
  重複した三角形を積み重ねるのではなく、自信を持ちます。
- 外部形状の詳細に寄与しない、囲まれた一致した共有ジオメトリを削除します。
- 重なり合わないソース ジオメトリを保持し、視覚的に確認できるようにあいまいな領域を公開します。
- 1 回のスキャンがより鮮明であるか、より詳細である場合、ソースごとおよび領域ごとの重み付けが可能になります。
- 合成後に水密性、境界、法線、寸法、トポロジーを検証します。
- 結合されたメッシュが再現できるように、ソースの出所と合成パラメータを記録します。
- 予想される三角形の数、境界、削除されたオーバーラップ、および信頼度分布を事前にプレビューします。
  合成結果をコミットします。

このワークフローは、大規模向けに計画されているものと同じアウトオブコア空間インデックスとワークユニット モデルを使用する必要があります。
メッシュ。統計的な比較と重複の統合も、ローカル全体に分散できる必要があります。
またはリモート MeshMill ノード。

## 分散合成

MeshMill クラスターは、複数のノード間で並行して動作する複数のノードを調整する必要があります。
ワークステーション。ノードは、割り当てられた領域を検査、選択、削減、検証、修復、または結合することができます。
作業単位。コントリビューションは、レビューされて組み込まれるまで、独立してバージョン管理されます。
共有オブジェクトバージョンに変換します。

システムは以下をサポートする必要があります。

- 複数のオペレーターと自動ノードからの同時貢献。
- 決定的なワークユニットの入力、パラメータ、依存関係、および出力。
- CPU、GPU、メモリ、アルゴリズム、現在の負荷に基づく機能認識スケジューリング。
- 依存関係を意識したメッシュ、領域、検証パス、合成ステージの分割。
- 一時停止、再開、キャンセル、再試行、再割り当て、障害回復を備えた耐久性のあるキュー。
- コンテンツアドレス指定されたアーティファクトとノード間の整合性チェック。
- 受け入れられた貢献バージョンの記録されたセットからの再現可能な合成。
- 後で同期できるオフラインまたは断続的に接続されたワークステーション。
- 参加ノードと共有プロジェクト データを明示的に制御するローカルファーストの操作。

## バージョン管理されたコラボレーション

すべてのコントリビューションは、その親オブジェクトのバージョン、選択された領域またはワークユニット、操作、
パラメータ、ノード ID、タイムスタンプ、依存関係、検証結果、出力チェックサム。

計画されたコラボレーション動作:

- プロジェクトには、オブジェクト、ブランチ、チェックポイント、コントリビューション、および合成されたバージョンが含まれます。
- 貢献者は互いに上書きすることなく、同じ親バージョンから作業できます。
- 重複しないコントリビューションは、検証後に自動的にマージできます。
- 重複するジオメトリや互換性のない依存関係により、明示的な競合が発生します。
- 競合により、視覚的な比較、リージョンレベルの選択、リベース、再実行、手動解決が可能になります。
- レビュー状態には、保留中、承認済み、拒否済み、優先済み、競合中、および統合済みが含まれます。
- 最終的な合成マニフェストでは、組み込まれたすべての貢献と依存関係が識別されます。

## 連携UI

デスクトップ アプリケーションは、別個のコマンドラインを必要とせずに分散作業を管理する必要があります。
またはサーバー管理ワークフロー。計画されたビューには次のものが含まれます。

- **プロジェクト:** オブジェクト、ブランチ、バージョン、貢献者、および合成ステータス。
- **クラスター:** 接続されたワークステーションとノード、機能、健全性、負荷、および現在の割り当て。
- **キュー:** 保留中、アクティブ、一時停止、ブロック、失敗、および完了したワークユニット。
- **貢献:** 作成者、ノード、親バージョン、影響を受ける領域、パラメータ、チェック、およびレビュー状態。
- **比較:** 同期された 3D ビュー、ジオメトリの違い、メトリクス、境界検査。
- **競合:** 重複領域、依存関係の競合、解決策の選択、および検証結果。
- **合成:** 依存関係グラフ、集計の進行状況、選択されたコントリビューション バージョン、および最終出力。
- **履歴:** ブランチ グラフ、チェックポイント、マージ、合成バージョン、再現性マニフェスト。

ビューポートには、所有権、割り当てられたリージョン、完了した作業、保留中の変更、競合、
基礎となるメッシュを変更することなく、バージョンの違いを修正できます。

## 調整と輸送

最初の設計フェーズでは、トランスポートを選択する前にプロトコルの境界を定義する必要があります。プロトコル
調整メタデータを大規模なメッシュ アーティファクトから分離し、再開可能な転送をサポートする必要があります。
外部アカウントやホストされたサービスがなくても、ローカル ネットワーク上で引き続き使用できます。

必要な調整の概念:

- コーディネーターの選出または明示的に選択されたコーディネーター。
- ノードの検出と手動ノード登録。
- 認証されたセッションとプロジェクトスコープの認可。
- 作品の所有権のリースとハートビート。
- 冪等な作業の提出と結果の受け入れ。
- 異なる MeshMill リリース間のバージョン ネゴシエーション。
- 進行状況、ログ、検証、失敗、再試行に関する構造化イベント。
- コーディネーター、ワークステーション、ネットワーク、またはノードの中断後の回復。

## 納品フェーズ

### フェーズ 0: コア外の大規模メッシュ処理

インデックス、ストリーミング、キャッシュ、ワークユニット、および安全性の契約については、次の文書に記載されています。
[`docs/OUT_OF_CORE.md`](docs/OUT_OF_CORE.md)。

- 完全なメッシュを割り当てる前に、三角形の数と作業メモリを推定します。
- 特大のバイナリ STL ファイルを、境界があり均等にサンプリングされたナビゲーション概要として開きます。
- フル解像度のジオメトリを、決定的なオーバーラップ境界を持つ空間立方体に分割します。
- CPU およびメモリ制限内で、独立したキューブを同時に読み取り、分析、最適化します。
- メモリ内に完全なメッシュを必要とする代わりに、粗いビューポート レベルから細かいビューポート レベルまでストリーミングします。
- キューブの状態をビューポートに直接描画します: キュー中、読み取り中、処理中、完了、失敗。
- 各キューブを埋めることでキューブごとの進行状況を表示し、高レベルのオブジェクト全体のビューを保持します。
- 境界検証、重複の削除、再現可能な設定を使用して、処理されたキューブを組み立てます。
- 後のフェーズでは、ローカル キューブ スケジューラを分散合成ワークユニットに拡張します。

### フェーズ 1: バージョン管理されたローカル基盤

- オブジェクト、オペレーション、コントリビューション、ブランチ、マニフェストの形式を定義します。
- ソースごとの可視性、変換、メタデータ、来歴を備えた複数の STL ワークスペースを追加します。
- 登録品質メトリクスと空間的重複分類を追加します。
- 重複したジオメトリや囲まれたジオメトリを削除しながら、統計的に一致するサーフェスを合成します。
- 1 つのソースに固有の競合、ギャップ、信頼性、ジオメトリの視覚的なレビューを追加します。
- アプリケーションセッション全体でローカル履歴を保持します。
- 視覚的なメッシュと領域の比較を追加します。
- 操作を決定論的で独立して再現可能にします。

### フェーズ 2: ローカルノードの調整

- 1 つのワークステーション上でワーカー ノードを実行します。
- キューイング、機能レポート、作業割り当て、キャンセルを追加します。
- MeshMill UI にノードとワークユニットの状態を表示します。
- パーティショニングと結果のアセンブリをローカルで検証します。

### フェーズ 3: マルチワークステーション合成

- 認証された LAN の検出と登録を追加します。
- 履歴書サポートにより、コンテンツに対応した作業入力と結果を転送します。
- 複数のワークステーション間での同時作業を調整します。
- ノードまたはネットワーク障害後に割り当てを回復します。

### フェーズ 4: 共同バージョン管理

- 寄稿者、ブランチ、レビュー状態、権限を追加します。
- 重複しない貢献をマージします。
- 重複または依存関係の競合を検出して解決します。
- 選択したコントリビューションを、再現可能なオブジェクト バージョンに合成します。

### フェーズ 5: 本番環境の強化

- プロトコルの互換性テストと混合バージョンの処理を追加します。
- 監査、整合性、破損、中断、回復のテストを追加します。
- スケジューリング、パーティショニング、転送、マージ、および合成のパフォーマンスをベンチマークします。
- 導入、バックアップ、移行、およびインシデントの回復を文書化します。
