# アルゴリズムのテストと貢献

MeshMill アルゴリズムは、その効果を可視化したまま、難しいジオメトリを管理しやすくする必要があります。
測定可能であり、結果が適用される前に元に戻すことができます。

## 参考治具

複合サンプル ジオメトリの両方のバンドル バージョンを使用します。

- `samples/sample-scan.stl` は、日常的な開発用の小型の通常の Git フィクスチャであり、自動化されています。
  チェックとコントロールの学習。
- `samples/original-scan.stl` は、大規模ファイルの動作、冗長レイヤー、 (Git LFS)
  不均一な密度、重なり、パフォーマンス作業。

冗長領域と密集領域は、意図的なテスト特性です。検査では彼らが対象になるかもしれないが、
重なり合うすべての表面が使い捨て可能であると想定すべきではありません。次の場合にコンパクトな合成メッシュを追加します。
変化には、既知の境界、曲率、トポロジー、密度、または重なりの不変条件が必要です。

## 比較チェックリスト

アルゴリズムまたはパラメータの変更については、次を記録します。

- MeshMill バージョンまたはコミット。
- 入力フィクスチャとチェックサム。
- アルゴリズム、品質プリセット、ターゲット、および詳細設定。
- 元の三角形と結果の三角形と頂点の数。
- 縮小率、寸法、および寸法ドリフト。
- パフォーマンスが関係する場合の経過時間とピークメモリ。
- 同じ保存されたビューと表示モードからのスクリーンショット。
- 目に見える境界、穴、自己交差、重なり、または歪みの変化。
- 結果がメッシュ全体の操作から得られたのか、それとも選択のみの操作から得られたのか。

別のプリセットと比較するだけでなく、同じターゲットでの現在の動作と比較します。
出力数が異なります。該当する場合は、シェーディング、密度、ワイヤフレーム、および頂点の表示を検査します。

## 受け入れ案内

最適化の変更により、予期しない寸法の変化、明らかな表面の反転、
処理された領域間の亀裂、意味のある境界の喪失、および大きな品質の低下が発生します。
同様の出力数。密度指向の変更は、除去された濃度が影響を及ぼしたことを実証する必要があります。
有用な曲率やトポロジーを持ちません。

パフォーマンス結果により、プロセッサ、メモリ容量、グラフィックス ハードウェア、オペレーティング システムが特定されます。
システム、入力サイズ、データがすでにキャッシュされているかどうか。構造の検証とスクリーンショット
レビューはサポートしますが、ソース ジオメトリに精通した寄稿者による検査に代わるものではありません。

## 回帰テスト

明示的な許容誤差を伴う決定論的なテストを優先します。新しいフィクスチャは通常の Git に十分な大きさに保ちます。
出所とライセンスを文書化し、実際のソース データが不要な場合は合成ジオメトリを使用します。
テストでは、操作によってジオメトリが変更される可能性がある場合、キャンセルと状態の復元をカバーする必要があります。
