# アウトオブコアメッシュアーキテクチャ

MeshMill の現在の大きなファイル保護機能は、完全なファイルを割り当てる前に作業メモリを推定します。
メッシュ。構成された予算を超えるファイルは、境界付きナビゲーションの概要として開くことができます。アン
概要はサンプリングされたジオメトリであり、それが視覚的に識別されるため、編集したりエクスポートしたりすることはできません。
それは完全なソースでしたが。

真のズーム依存の詳細には、永続的な空間インデックスが必要です。以下の設計はそれを定義します
次の実装フェーズ。

## インデックス形式

各ソース メッシュは、以下を含むバージョン管理された `.meshmill-index` ディレクトリを受け取ります。

- `manifest.json`、ソース サイズ、変更時間、サンプリングされたコンテンツのハッシュ、境界、
  三角形の数、インデックスのバージョン、座標の精度、およびレベルの説明。
- オクツリーレベルとモートンコードによってアドレス指定される空間タイル。
- 占有されているすべての親タイルの粗い表示メッシュ。
- リーフ タイル内のフル解像度のトライアングル レコード。そして
- 境界の所有権と、地域の操作とアセンブリ中に使用されるオーバーラップメタデータ。

インデックスの作成では、ソースが境界付きブロック内で順番に読み取られます。一時的なタイルランを書き込み、
すべての必要なファイルが検証に合格した後、マニフェストをアトミックに公開します。中断された、または
古いインデックスはマニフェストから検出され、完全なインデックスを開かなくても再開または再構築できます。
メモリ内のメッシュ。

## ビューポートストリーミング

ビューポートは、カメラ錐台と画面空間エラーを使用してタイルを選択します。粗い親タイルは
最初に示されています。表示されている子タイルは、画面外でカメラが近づくとそれらを置き換えます。
衝撃の少ないタイルは粗いままです。 RAM と VRAM には独立した予算があり、最も最近使用されていない予算があります。
キャッシュ。ディテールを解放しても、オブジェクト全体の粗い表現は決して解放されません。

スケジューラはタイルの状態を記録します: キューイング、読み取り、処理、アップロード、常駐、失敗、
そしてキャンセルされました。ビューポートは立方体を状態ごとに色付けし、各立方体をその状態に応じて塗りつぶすことができます。
進歩。キャンセルすると部分的な結果が削除され、最後の完全な表現がアクティブなままになります。

## 処理と容量

ローカル ワーク ユニットは、タイルにその操作に必要な決定論的なオーバーラップを加えたものです。同時実行性
現在利用可能な RAM、構成されたメモリの割合、論理プロセッサ数、および
測定されたワークユニットのサイズ。 GPU のアップロードと表示には、別個の VRAM 予算があります。並行して報告
容量は、代表的なタイルが測定されるまでの推定値です。

操作では、境界要素ごとに 1 人の所有者が保持されます。アセンブリは共有境界を検証します。
重複を削除し、数と範囲をチェックし、使用された正確なパラメーターを記録します。同じ作品
ユニットと結果のフォーマットは、後で分散合成ノード全体でスケジュールできます。

## 安全規則

- グローバル サンプルには、フル解像度のビューポートの詳細ではなく、概要としてラベルが付けられます。
- 概要は、完全なソース メッシュとして上書きまたはエクスポートすることはできません。
- 現在の予算を超える全負荷リクエストには、明示的な選択が必要です。
- インデックスの生成、タイルの処理、およびアセンブリは引き続きキャンセル可能で、以前の内容が保持されます。
  完成した状態。
- 容量値は推定値であり、現在のエンジンを表すか、計画されたエンジンを表すかを識別します。
  タイルの並列実行。
