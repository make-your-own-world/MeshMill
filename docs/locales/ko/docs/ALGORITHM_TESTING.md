# 알고리즘 테스트 및 기여

MeshMill 알고리즘은 효과를 눈에 띄게 유지하면서 어려운 형상을 관리하기 쉽게 만들어야 합니다.
측정 가능하며 결과가 적용되기 전에 되돌릴 수 있습니다.

## 참조 설비

복합 샘플 형상의 번들 버전을 모두 사용합니다.

- `samples/sample-scan.stl`는 일상적인 개발을 위한 더 작은 일반 Git 고정 장치이며,
  확인하고 컨트롤을 학습합니다.
- `samples/original-scan.stl`는 대용량 파일 동작, 중복 레이어, (Git LFS)
  고르지 않은 밀도, 중첩 및 성능 작업.

중복되고 밀집된 영역은 의도적인 테스트 특성입니다. 테스트는 그들을 대상으로 할 수 있지만
겹치는 모든 표면이 일회용이라고 가정해서는 안 됩니다. 다음과 같은 경우 컴팩트한 합성 메쉬를 추가하세요.
변화에는 알려진 경계, 곡률, 토폴로지, 밀도 또는 중첩 불변이 필요합니다.

## 비교 체크리스트

알고리즘이나 매개변수 변경의 경우 다음을 기록하십시오.

- MeshMill 버전 또는 커밋;
- 입력 설비 및 체크섬;
- 알고리즘, 품질 사전 설정, 대상 및 고급 설정;
- 원본 및 결과 삼각형 및 꼭지점 개수
- 감소율, 치수 및 치수 드리프트;
- 성능과 관련된 경과 시간 및 최대 메모리
- 동일한 저장된 보기 및 디스플레이 모드의 스크린샷
- 가시적인 경계, 구멍, 자기교차, 중첩 또는 왜곡 변경;
- 결과가 전체 메시 또는 선택 전용 작업에서 나온 것인지 여부.

동일한 대상의 현재 동작과 비교하고, 다른 사전 설정과도 비교합니다.
출력 개수가 다릅니다. 해당되는 경우 음영처리, 밀도, 와이어프레임 및 정점 표시를 검사합니다.

## 수락 안내

최적화 변경은 예상치 못한 치수 변경, 명백한 표면 반전,
처리된 영역 간의 균열, 의미 있는 경계의 손실 및 대규모 품질 회귀
비슷한 출력 개수. 밀도 중심의 변화는 제거된 농도가
유용한 곡률이나 토폴로지를 갖지 않습니다.

성능 결과는 프로세서, 메모리 용량, 그래픽 하드웨어, 운영 체제를 식별해야 합니다.
시스템, 입력 크기 및 데이터가 이미 캐시되었는지 여부. 구조적 검증 및 스크린샷
검토를 지원하지만 원본 형상에 익숙한 기여자의 검사를 대체하지는 않습니다.

## 회귀 테스트

명시적인 허용오차가 있는 결정론적 테스트를 선호합니다. 일반 Git에 맞게 새 픽스처를 충분히 작게 유지하세요.
원본과 라이선스를 문서화하고 실제 소스 데이터가 필요하지 않은 경우 합성 기하학을 사용합니다.
테스트에서는 작업이 형상을 수정할 수 있는 경우 취소 및 상태 복원을 다루어야 합니다.
