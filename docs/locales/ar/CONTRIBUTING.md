# المساهمة

المساهمات هي موضع ترحيب من خلال القضايا وطلبات السحب.

## نطاق المشروع

MeshMill يجعل الملفات الشبكية كبيرة الحجم أو الكثيفة أو الصعبة قابلة للإدارة من أجل التحرير النهائي و
سير عمل الإنتاج. يجب أن تعمل المساهمات على تحسين الفحص الهندسي والكثافة الشبكية والنقطة
الإدارة، التحسين، الاختيار، الاقتصاص، التنظيف، التحقق من الصحة، تبادل STL، الأداء،
أو تنسيق تلك العمليات.

لا يشمل المشروع النمذجة للأغراض العامة، النحت، الرسم، الرسوم المتحركة، العرض،
تكوين المشهد أو المواد أو المعدات أو أنظمة إنشاء المحتوى الأخرى. المقترحات التي تقدم
هذه الميزات خارج نطاق المشروع.

يجب أن تحافظ الميزات الجديدة على تركيز التطبيق، وتحافظ على سير العمل المباشر الذي يتحول إلى مصدر
الهندسة إلى شبكات يمكن التحكم فيها، وتجنب تحويل عناصر التحكم الداعمة إلى تحرير عام
بيئة.

## التعريب

يتم تخزين نص مصدر واجهة المستخدم باللغة الإنجليزية في `locales/en-US.json`. يتم تخزين بيانات التعريف المحلية في
`locales/manifest.json`. تستخدم كتالوجات واجهة المستخدم المترجمة نفس المفاتيح الثابتة واسم الملف
`<locale>.json`. تستخدم الوثائق المترجمة اسم الملف الجذر المطابق ضمن
`docs/locales/<locale>/`.

يتم إنتاج الترجمات في البداية باستخدام خدمات الترجمة الآلية الخارجية واستلامها
التحقق الهيكلي الآلي. لا يمكن لهذه العملية أن تضمن الحصول على نتائج طبيعية أو دقيقة من الناحية الفنية أو
اللغة الصحيحة من حيث السياق. يتم تشجيع المتحدثين الأصليين على مراجعة واجهة المستخدم المترجمة وتصحيحها
النص والتوثيق. يجب أن تحافظ تصحيحات الترجمة على مفاتيح الكتالوج، والعناصر النائبة،
الأوامر والروابط والقياسات وأسماء المنتجات وهيكل تخفيض السعر.

بعد تغيير التسميات أو تلميحات الأدوات أو مربعات الحوار أو أي نص آخر مرئي للمستخدم، قم بتشغيل:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
```

قم بمراجعة تغييرات المصدر والمفاتيح المعاد إنشاؤها معًا.

## التغييرات الهندسية والخوارزمية

استخدم هندسة العينة المجمعة عند تغيير التحسين، وتحليل الكثافة، والتحديد، والاقتصاص،
التعامل مع الملفات الكبيرة، أو سلوك مقارنة إطار العرض. أنه يحتوي عمدا على طبقات زائدة عن الحاجة
والكثافة غير المتساوية، لذا فإن النتيجة المفيدة يجب أن تعمل على تحسين الإدارة دون إخفاء التشويه،
تجاهل الحدود ذات المعنى، أو إزالة الهندسة التي تحتفظ بها خوارزمية أخرى بصمت.

تسجيل المدخلات، والخوارزمية، والإعدادات، وعدد المثلثات، والأبعاد، وانحراف البعد، والوقت المنقضي،
ولقطات الشاشة ذات الصلة لإجراء المقارنات. اختبر كلاً من تركيبات Git العادية الأصغر حجمًا، وعندما
يتعلق التغيير بالهندسة الكبيرة أو ذات الطبقات، وهي تركيبات Git LFS الأصلية. لا تقم بضبط الخوارزمية
لهذه المباراة وحدها. أضف حالات اصطناعية صغيرة للكائن الثابت أو الانحداري المحدد
تم اختباره.

راجع [اختبار الخوارزميات والمساهمة](docs/ALGORITHM_TESTING.md) للحصول على قائمة مراجعة المقارنة.

## إعداد التطوير

1. قم بتثبيت Python 3.12 64 بت على Windows.
2. إنشاء وتفعيل بيئة افتراضية.
3. تثبيت `requirements-dev.txt`.
4. قم بتشغيل `python meshmill.py` لواجهة المستخدم الرسومية أو `python meshmill.py --help` لاستخدام واجهة سطر الأوامر (CLI).
5. قم بتشغيل `python -m py_compile meshmill.py` قبل إرسال التغيير.

احتفظ بالشبكات الخاصة والملفات التنفيذية التي تم إنشاؤها ولقطات الشاشة التي تحتوي على معلومات خاصة والمحلية
بناء الدلائل من الالتزامات. هندسة الاختبار القابلة لإعادة التوزيع تنتمي إلى `samples/` مع
المصدر والترخيص والأبعاد وطريقة الإنشاء موثقة. يجب أن تستخدم الملفات المصدر الجديدة ملحق
معرف SPDX `GPL-3.0-or-later`.

قم بقص كل لقطة شاشة للوثائق إلى محتوى تطبيق MeshMill. لا تشمل
شريط المهام أو نافذة Chrome غير ذات الصلة أو الإشعارات أو تفاصيل الحساب أو المسارات الخاصة أو الخلفية
محتوى سطح المكتب.
