# الافراج عن MeshMill

يبني مسار الإصدار عناصر Windows على متسابقي Windows المستضافين في GitHub. يتلقى المستخدمون النهائيون
برنامج تثبيت مستقل أو ملف ZIP محمول ولا تقم بتثبيت Python أو Node.js أو التبعيات.

قبل إنشاء كتالوجات مصادر الترجمة، قم بتحديثها والتحقق من صحتها:

```powershell
python tools/localization/extract_ui_catalog.py
python tools/localization/validate_locales.py
python tools/release_privacy_check.py
```

## قبل الإصدار العام الأول

1. قم بإنهاء والتحقق من صحة التطبيق المخطط له وترجمات الوثائق.
2. قم بمراجعة GPL وإشعارات الجهات الخارجية.
3. اختبار التثبيت، والتشغيل، وتحميل STL، وتحسينه، وتصديره، وإلغاء تثبيته على نظام نظيف
   حساب Windows أو الجهاز الظاهري.
4. قم بتشغيل CI ضد `samples/sample-scan.stl`. افحص كل لقطة شاشة للوثائق واقطعها
   شريط المهام، نافذة الكروم التي ليست جزءًا من MeshMill، الإشعارات، المسارات الخاصة، الحساب
   التفاصيل ومحتوى سطح المكتب غير ذي الصلة قبل النشر.
5. قم بتكوين مؤلف Git للمستودع المحلي باستخدام عنوان عدم الرد GitHub الخاص بالحساب قبل
   الالتزام الأول. قم بتأكيد ذلك باستخدام `git config --local --get user.email`.
6. قم بتكوين أسرار توقيع رمز المصادقة الاختيارية:
   - `WINDOWS_CERTIFICATE_BASE64`: شهادة PFX بتشفير Base64.
   - `WINDOWS_CERTIFICATE_PASSWORD`: كلمة مرور PFX.

بدون شهادة توقيع، ستظل الملفات التي تم إنشاؤها تعمل، ولكن قد تظهر Windows SmartScreen
تحذير من ناشر غير معروف. لا تصف الإصدارات غير الموقعة بأنها موقعة أو موثوقة.

## المسح الأصلي وGit LFS

يتم تتبع `samples/original-scan.stl` من خلال Git LFS لأنه يتجاوز 100 MiB العادي لـ GitHub
حد الملف. قبل الالتزام الأول، تحقق مما يلي:

```powershell
git check-attr filter -- samples/original-scan.stl
git lfs pointer --file samples/original-scan.stl
```

يجب أن يكون عامل التصفية `lfs`، ويجب أن يتطابق معرف كائن المؤشر مع `samples/SHA256SUMS.txt`. الافراج
يقوم سير العمل بفحص محتوى LFS وينشر STL الأصلي كأصل إصدار منفصل. يستخدم سي.آي
نموذج Git العادي الأصغر ولا يقوم بتنزيل كائن LFS.

## اختبار بناء الإصدار دون النشر

افتح **الإجراءات**، وحدد **إصدار**، واختر **تشغيل سير العمل**، وأدخل إصدارًا رقميًا مثل
`0.1.0`. يقوم التشغيل اليدوي بتحميل عناصر سير العمل للاختبار ولكنه لا يقوم بإنشاء GitHub عام
الافراج.

## نشر بيان

من فرع `main` النظيف والمراجع:

```powershell
git tag -a v0.1.0 -m "MeshMill 0.1.0"
git push origin v0.1.0
```

تبدأ العلامة سير عمل الإصدار. هو:

1. تثبيت تبعيات البناء المثبتة؛
2. ينشئ بيانات تعريف إصدار Windows المطابقة؛
3. إنشاء ملفات تنفيذية قائمة بذاتها لواجهة المستخدم الرسومية وواجهة سطر الأوامر؛
4. يوقع الملفات التنفيذية عند تكوين أسرار التوقيع؛
5. إنشاء برنامج تثبيت Inno Setup لكل مستخدم؛
6. يوقع المثبت عند تكوينه؛
7. يقوم بإنشاء ملف المجموع الاختباري ZIP وSHA-256 المحمول؛
8. تحميل عناصر سير العمل؛
9. يقوم بإنشاء إصدار GitHub للعلامة المدفوعة.

تحقق من برنامج التثبيت والأرشيف المحمول على نظام Windows النظيف قبل الإعلان عن الإصدار.
احتفظ بالمصدر المطابق لكل ثنائي موزع متاح تحت نفس علامة الإصدار.
تأكد من أن زر GitHub يشير إلى عنوان URL النهائي للمستودع العام قبل وضع علامة على الأول
الافراج.
